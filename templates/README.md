# 内置书与统一表单模板

插件随版本携带三类书：`tisya-template-book.json`（缇斯亚模板书）、`tisya-extension-book.json`（缇斯亚扩展资料书）、`tisya-beauty-book.json`（缇斯亚美化书）。启动时自动安装和检查。所有新条目默认关闭原生注入；模板只在新内容创作读取，扩展与美化定义由对应编译器读取，普通自定义资料条目沿原生条件扫描。

每条内置定义使用独立于标题和 UID 的稳定编号。更新比较“上次插件原文／当前正文／新插件原文”：用户没有修改的管理字段可更新，用户改文保留；两边同时变化时保留当前内容并在用户身份页列出冲突。用户自建条目、启用状态、关键词、顺序等配置保留。删除过的管理条目不会在启动时悄悄补回。同名未认证条目不会自动认领。保存后必须完整回读确认，某本失败会留下明确状态，其余书可以完成。

## 世界、人物和小手机共用一个数据库

`world-form.json` 与 `character-form.json` 是程序使用的字段填写计划，列出规范表和关联方向，不是运行状态。新世界／人物创作读取本次实际注册的表单，在完整回复的 `cells` 区块填写可读简表；程序负责将它解析为同一规范数据草稿，用户核对后统一提交。当前世界时间唯一来自 `X_WORLD_CLOCKS`，人物档案来自 `T_CHAR_DOSSIER`，身份实体通过 `M_FIELD_REFERENCES` 引用原点；余额等业务也只写规范表。模板更新不覆盖现有实例。

人物编辑先显示字段差异，再确认提交。身份页选择世界基点书和角色条目，原文资料通过“交给缇斯亚助手提炼”进入同一创作页，已有规范表单则可预览采用。来源在生成返回及提交前再次核对，变化时保留草稿并报错。已迁移人物须由真实回执证明归属，才能沿原档案与原点引用修订；整段原文不能再写入本领外显表现，人工填写的现有值受到保护。完整原文及旧手机初始化块保留在来源中；手机业务迁移另行核对。未动字段不写入，未知不补零。资料书及手机世界选择只保存当前聊天的定位引用。世界画风、应用和业务配置保存在选中世界的关联表；不另建一份手机初态数据库。作者原文保留为来源，不能盖过数据库当前值。

具体输出与来源规则见 `form-authoring.md`。创作保留当前完整 `reply` 框架，以下仅展示其中 `cells` 的填写方式；表名、行号、字段名和类型均以本次实际提供的表单为准：

```text
【本次登记的表名／1】
行号 字段名：填写内容
```

这只是格式示意，不作为实例事实。模型填写可读内容和登记的关联名称，程序生成内部编号、字段路径、主体关联、来源与保存回执。派生字段与程序回执不填写；未提供内容保持未知，需要新定义时先进入 schema 审查。模型不输出嵌套存储 JSON，也不自行宣称已保存。导入书及本说明所引用的填写规则由 `npm run build:builtin-books` 从当前工厂生成并校验。

## 旧版迁移材料

`phone-world.json`、`phone-character.json` 与 `phone-fields.md` 保留为旧版只读迁移说明，不能再用于创建独立手机运行态。旧书中的 `<手机世界>`、`<手机初态>` 及旧模板条目保留原文、UID 与摘要；新模板读取明确排除这些旧条目。迁移必须先与现有统一表单对照，显示冲突并通过统一提交入口保存，不能覆盖已推进的时间或财务状态。

旧版本“更换世界编号须另开聊天”和“金融机制变化拒绝隐式迁移”的保护语义仍适用于旧存档导入；当前选择只改变引用，不自动迁移事实。已有存档的财务机制变更须单独展示迁移差异并确认；书更新与界面重开都不执行它。

## 美化协议边界

现行 25+2 内容通道以及旧 `〔名称:参数〕…〔/名称〕` 标记继续保留。`record` 消息子类型是本轮新增协议，不声称还原 Vic 的旧原语法。`T_DYN_MESSAGE_CONTENT.media_ref` 指向 `T_SYS_MEDIA_ASSETS`，`transfer_ref` 指向 `X_FIN_TRANSACTIONS`；展示转账卡片不会再次扣账。
