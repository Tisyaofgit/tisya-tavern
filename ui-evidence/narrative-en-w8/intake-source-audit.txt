NECESSARY GATE FOLLOW-UPS FOR ROOT TO APPLY

1. New input now explicitly clears DONE(INNER_END) and DONE(COMMIT.READY). The old “discard readiness” could be read as including these, but leaving them named only at the end of the pipeline made reset semantics incomplete.
2. Same-input new/changed source material or actual tool results invalidate affected @IN references, readiness and draft checks. INNER.LOGIN should enforce relocking and reference revalidation before creation resumes, not only after prose edits.
3. An unsent-draft revision should clear frozen/completion bindings for the affected revision as well as LOCK/FORMAT. Reuse checks only where the verified dependencies are unchanged; current-draft correctness cannot be inferred from an earlier DONE marker.
4. Bind DONE(INNER_END), COMMIT.READY and @execute to the same actual input and frozen draft revision. The old gate already said “for this revision”; the final transition should consume that fact rather than a bare truthy marker.

These are prompt-contract completeness changes, not actual software state machines or proof that a model cannot violate them.
