# P1—P4 表单与运行框架统一审计

日期：2026-11-27
范围：主 API 四区块、六类提案与 P4 专项重绘、表单目录与编译、引用和数量输入、历史上下文、时间轴召回、最终投影缓存、Matrix 权威存储、宿主事务入口、旧世界书表单链退役，以及上述模块的直接调用方。本文只报告本次审计范围，不宣称全库再无可重构内容。

## 一、审计结论

本轮把 P1—P3 作为同一批变更处理，没有分别冻结表单或提示词。主回复的 `body／cells／archive／proposals`、表单编译与采用、历史分层、按需召回和短工作区均接到既有 Matrix 服务，没有新增第二权威数据源或第二提交链。

字段审计工具的当前结果为：目录表 207、运行时表 225、字段 3355、模型可读字段 1905、模型可写字段 1750、显式引用 739、派生定义 60，结构错误 `errors: []`。旧字段来源扫描覆盖 459 个旧字段 ID、495 个落位；其中 23 个旧 ID 是一对多展开，带 `legacy_source_ids` 的字段均保留来源标签和来源类型。这里的“一对多”是字段职责拆分，不按丢失或重复存储处理。

## 二、本轮已统一的能力

### 1. 主回复与提案

- 主 API 同一回复承载正文、实时单元、归档和知识／偏好提案。
- 六类提案共用 `pending → accepted／rejected／redraw_pending` 生命周期；待确认和拒绝内容不进入投影。
- 打回保留原提案 ID、原快照与修正指令；采用复用 Matrix Runtime 事务、CAS、schema、引用检查、图鉴增量索引和最终投影。
- `event_chain → cells／archive`、`global_knowledge → proposals`、`object_archive → cells` 是输出职责映射，不是三套数据库。

### 2. 表单、引用与数量

- 表单准备、接受和变更应用继续由 `prepareMatrixSheets()`、`acceptMatrixSheets()`、`applyMatrixChanges()` 统一处理。
- 引用按目标表、名称、别名、完整标题和本批分组序号解析。裸序号只有在已有解析无唯一结果、输入为正整数且字段只有一个目标表时才启用；跨表数字、事件编号和歧义仍失败关闭。
- `parseQuantityNumber()` 与 `parseQuantityShorthand()` 统一支持中文数字、“半”及“半寸／半步／半米”等精确半量简写。纯 `NUMBER` 不接收描述性修辞；`M_QUANTITIES` 才使用数量和描述状态。
- 未知单位、错误缩写和不可数值化描述不会被静默改写为数字；单位仍由既有单位注册服务持有。

### 3. 历史与时间轴

- 普通主上下文只保留链头快照：上轮用户、上轮正文和本轮用户。较早正文保留在权威来源库，不另建正文副本槽。
- 较早正文退出普通上下文后，不再因其旧格式损坏阻断链头；一旦被时间轴召回，仍必须通过批准来源、正文 hash、段落 hash、分支和披露锁检查。
- 统一时间轴召回携带事件编号、时间线域、故事时间、触发线索、来源楼层和段号；排序优先故事时间，再按来源位置。
- 历史预览 UI 已改为“统一时间轴”和“链头快照”，不再展示空的近期正文面板。

### 4. 短工作区与唯一权威存储

- 最终投影缓存可持久化短工作区，省略可由权威来源重放的 `journal.entries`，保留当前状态、材料和审核证据。
- 轻量头仍核对修订、随机 token、消息、手机、主控绑定和审核模式证据；正文变脏、token 改变或修订不一致均不能复用。
- 冷恢复只复用派生结果。回放、历史快照、数据库读取和 CAS 提交前通过 `authoritativeWorkspace()` 补载唯一权威 bundle，并核对修订。
- `compactRuntimeWorkspace()` 不修改原 bundle；短工作区不是权威存档，也不能作为提交输入。
- 引擎工作区原来在 `controller.mjs` 中自行打开 IndexedDB 的旁路已移除，打开、普通读写和事务错误处理改走 `idb-framework.mjs`。同库扫描中，`indexedDB.open` 只保留在该统一框架内。
- 多请求 CAS 提交仍在一个 IndexedDB 事务中比较 bundle 与轻量头、保留无变化 token、拒绝同修订不同内容；没有以“先读后写”的非原子操作替代它。

### 5. P4 专项重绘与旧链退役

- 打回后的偏好提案复用既有 `preferenceAnalysis` 路由，其他知识提案复用 `objectArchive`；请求仍由 `config/host.js` 的任务注册、专用预设、传输和取消信号负责。
- `redrawMainProposal()` 只允许修改同一 `tableId／recordId` 的一条提案。专项响应不能写故事、归档、其他提案或审核内部字段；重绘通过 `revise` 回到 `pending`，不直接创建正式偏好或知识记录。
- 最终采用仍只能进入 `reviewMainProposal()` 的 Matrix 审核事务，保留 CAS、上下文身份、引用检查、写后回读和失败关闭。
- 表格组合根现在强制要求 Matrix database 与 host；初始化提炼仍通过只读 `books.cardBooks()` 获取角色卡来源，不再保留旧世界书业务写入。
- 旧账本、旧归档工具循环、旧 origin/session 提交、旧 OnePass 写表分支和对应专用测试已按生产 import 图整链删除。OnePass 展示、回复解析、预设与注入不在删除范围内。
- 正文证据提取统一由 `engine/reply.mjs` 提供；面板、历史、提炼、条件和偏好 UI 均复用现行服务，不再保留“请先迁移”的旧入口 stub。

## 三、没有强行合并的合法差异

| 项目 | 当前边界 | 不能简单统一的原因 | 纳入可能性与建议 |
|---|---|---|---|
| 无显式 `ref` 的 184 个 REF／CHILD_REF 字段 | business 58、executor 24、program 72、internal-or-projection 30 | 手机命名空间、执行器目标和内部投影可运行时解析；静态目录无法穷举动态目标 | 可以加强审计，不应全部补固定 `ref`。后续让动态提供方输出机器可读解析报告，将“动态已声明”和“确实缺少目标”分开计数 |
| `duplicateProjectionDefinitions: 45` | 同一事实在模型、UI 或读者视图中的投影定义 | 同名投影不等于第二持久真相；字段审计未发现结构错误 | 可继续核对派生公式是否有重复实现，但不能按名称删字段；只有能从唯一规范重算且不改变权限的投影才可合并 |
| `fieldsFor`／字段枚举 | 审核目录、补录目录、UI 控件查询 | 有的合并自定义字段，有的查 DOM，有的施加只读权限 | 可统一“目录字段枚举”纯函数，但不得把权限判断或 DOM 查询塞进底层服务 |
| `run／draw／render／save／commit` 同名方法 | UI 绘制、服务串行队列、IndexedDB CAS、Runtime 事务 | 同名不代表同能，事务边界和副作用不同 | 保持语义名称与现有组合根；只对调用图证明相同的实现做迁移 |
| 原始正文 hash、来源 hash、操作 hash | 防脏证据、来源完整性、幂等回执 | 输入域和安全目的不同 | 可共用摘要算法，不合并摘要内容或证据键 |
| Reader 正式生成物与 `reader-compat.js` | 正式协议与旧宿主显式适配 | 宿主生命周期不同 | 适配继续限制在兼容层；协议能力沉降后删除对应适配，不保留永久双链 |
| 媒体库与 Matrix bundle | 二进制媒体存储；业务状态与日志 | 媒体字节不能由业务 journal 重算，事务容量和生命周期不同 | 保持不同权威记录，但共用 IndexedDB 打开、事务、搬迁和校验框架；不并入整份 bundle |
| 全局偏好工作区 | 独立 scope 的 Matrix state | 跨故事偏好不属于某一聊天 owner | 已复用 Runtime、CAS 和操作回执；无需把记录复制进每个聊天 |
| 预览、Chromium 与真实宿主 | 开发和合成回归环境 | 不能替代真实 SillyTavern、真实模型和 Android 生命周期 | 保留各自验收职责，报告中分别声明，不能互相冒称 |

## 四、本轮实际清理与对抗回归

- 删除普通主上下文对较早 assistant 正文的依赖，历史来源仍完整保留。
- 删除空的近期正文预览面板，避免 UI 暗示存在第二正文层。
- 移除引擎工作区私有 IndexedDB 打开与普通事务封装，纳入统一底层框架。
- 引用序号回归证明：本批 `last_transfer_ref` 和 `holding_ref` 可解析，缺少目标事件的 `event_ref:'1'` 仍失败。
- 数量回归证明：“半寸／半步／半米／0.5米”可用，近似和描述型数量仍按字段语义处理。
- 短工作区宿主回归证明：冷恢复读取命中工作区；提交前补载权威日志；原日志不被裁剪；旧操作回执保留；正文变脏后工作区不命中。
- 架构回归禁止 `controller.mjs` 再出现直接 `indexedDB.open()`。

## 五、后续可优化项（不属于本轮已完成）

1. **动态引用机器可读报告**：为 `phoneFormReference()` 和执行器引用提供方增加统一诊断接口，逐项列出目标提供者、解析时点和失败关闭方式。可纳入统一审计，不必统一成静态引用。
2. **短工作区进一步分块**：当前只省略 `journal.entries`；`state`、`manual_edits`、`turn_review` 等仍保留。后续应先做体积与访问频率测量，再按脏块持久化，不能宣称所有大对象已消除。
3. **派生缓存失效粒度**：目前以完整证据判断缓存是否可复用。可在保持证据强度的前提下分块 hash，减少大工作区的序列化成本；不得为提速取消消息或手机证据。
4. **旧链防回退**：保留 Matrix-only 组合根、旧写入符号清零和 P4 单审核事务的对抗测试；新增能力先检索既有任务与服务，不重新引入旧世界书业务写入或兼容包装。
5. **目录枚举纯工具**：若后续调用方继续增加，可把不含权限判断的字段枚举提取到既有目录服务；先补调用图和行为对照，避免循环依赖。
6. **真实环境性能验收**：仍需分别实测真实宿主冷打开、长聊天重进、真实模型生成和 Android 实机；单元测试与合成存储不能给出这些结论。

## 六、验证边界

本文件记录代码和合成回归审计，不替代真实环境验收。最终统一编排器以单并发从零运行，并按用户决定排除 `phone*.test.js`：`275` 个非手机文件，`tests=4358，pass=2483，fail=0，cancelled=0，skipped=1875，todo=0`，满足 `4358 = 2483 + 0 + 0 + 1875 + 0`。`shell.test.js` 的 125 个顶层测试按精确名称分片，过滤产生的 skipped 未计入 pass。30 个手机测试文件不在本轮通过结论内，手机接入将另行重做。

P4 另有 Chromium 实际点击核验：生产 Matrix host、组合根与偏好 UI 配合隔离合成数据和真实 IndexedDB，完成“主回复生成待确认提案 → 打回 → 专项重绘仍为待确认且正式记录为零 → 用户采用后正式记录为一”。390px 布局无横向溢出，页面业务错误为空；合成响应不代表真实模型质量。

排雷期间曾出现环境清理删除依赖与 `.git`、重文件超时和一次构建器目录读取资源错误；这些均未计为业务通过。退役页面与冻结服务夹具已迁移到当前 Matrix 页面和组合根，上述最终数字来自修复后的完整从零重跑，不由旧结果拼接。扩展正式构建及 `--check`、`git diff --check` 与退役符号扫描通过。

当前没有真实 SillyTavern、真实模型或 Android 实机验收结论。本次变更尚未提交或推送。
