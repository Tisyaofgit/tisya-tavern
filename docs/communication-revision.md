# 本轮要求与定向重骰 · 31.10

## 使用

- 日常继续使用原生 RP 输入框与发送按钮。“本轮要求”默认折叠；有草稿显示圆点，折叠不取消附带。
- 两框同发时，RP 留在原生用户消息中；要求以独立、明确标记的本轮消息进入请求，不冒充角色台词或既成剧情。消息要求保存成功并准备发送时清空要求，停止、空回复和失败恢复草稿。
- 只想评论作品或询问缇斯亚时，将本轮要求的发送方式切换为“与缇斯亚交流”，仍使用主发送键。沿用已有连接与模型配置发起一次独立请求；回应留在场外面板，不推进故事、不更新表单、不代为宣布已修改偏好。
- 普通“重骰”一键生成，不注入高级改写指令。更多中的“高级”单独进入修改页。正文长按“修改”后可多选，选中段落标红，✓ 进入指令页；可以填写“修改指令”和“新增细节／发展方向”。保留旧候选。
- 用户 RP 的长按“修改”打开手动编辑器，不能把用户消息当成角色候选重骰。正文显示若被原卡合并、改写而无法准确对应原段落，会明确提示使用高级页，不猜段号。
- 菜单“沉浸全屏”沿用宿主原生设置入口；只有宿主支持时提供，不用页面样式假装隐藏安卓状态栏。
- 局部模式默认要求未选正文段落逐字不变，越界会退回旧候选并显示原因。额外勾选“全篇用词优化润色”允许全篇措辞变化，仍要求未选段落的事实和走向不变；事实等价没有自动语义证明，应对照候选审阅。增加新段落请选择全文模式。
- 左右候选按钮使用宿主原生 swipe。较早楼层先建立分支，避免删除原聊天后文。原生 RP 草稿未清空时，主动重骰会提示先处理草稿，以免宿主误带入。

## 与表单工作区衔接

复用并行 alpha32 恢复工作区的 revision 控制器、圆形按钮素材和图标；仅将适配正式 main 的小范围改动合入。没有整体合入尚在推进的表单工具循环、档案审核或偏好引擎，也没有改写并行工作区文件。

`revision.js` 管重骰请求与原生候选生命周期；`revision-ui.js` 管选段与修改表单；`communication.js` 管场外草稿、请求和反馈。`config/host.js` 统一附加指令，保留原路由、输出协议与传输检查。原生候选正文仍由宿主管理。

场外数据存放当前 chatMetadata 的“缇斯亚场外交流”，按世界／会话与可用 persona 标识隔离。暴露 `window.Tisya.communication.read()` 只读快照供后续偏好服务取证；不另建可编辑偏好真源。反馈仅作为证据，当前版本不自动学习、不提升为长期规则。

表单旧楼层分支支持 `stageFork(floor, keepFuture, {preserveCandidates:true})`：保存可切换候选所对应的提交，排除后文提交，不将被重骰候选冻结成无来源的基础事实。分支激活合并并发入口为一次写入。重骰失败不归档，成功后的归档仍经原表单服务；旧候选恢复依有效来源投影。

接续表单分支时须保留其新版 `storySources`、`contextSource`、`originPinsAtStart` 和工具轮投影，不能以本版兼容 main 的旧 ledger 接口反向覆盖新内核。整合 `communication` 任务与 native send 钩子时保留独立作用域和取消检查。

## 验证边界

本地测试覆盖两框请求装配、折叠草稿、空输出／停止／失败、跨聊天与 persona、字面内容注入、原生候选恢复、局部越界、全篇润色开关、旧楼层分支和表单事实排除。圆框素材来自已确认候选，保留 44px 点击区域。

未完成 Android 安装、长按触控与键盘实测；本版没有新增付费模型效果测试。全局／user 卡双尺、多格喜恶、N 轮静默学习和预设重构仍是后续工作，不能以此版的反馈记录入口冒充完成。

## 显示与性能衔接（31.10）

`paragraph-actions.js` 使用 composedPath 支持消息 Shadow DOM，监听只覆盖本聊天正文；原始段落是修改依据。滚动/取消打断长按，源文变化清理红选。系统文本选择只在正文屏蔽，输入框仍保持原生选字。

原卡动态面板仍由酒馆助手拥有。`native-panels.js` 记住已经核对的公开 frame 根；helper 删除原 code 后不丢失身份。世界球开合桥接可见性，独立的自有行动尾部位于原卡面板后，避免搬动 iframe 造成重新加载。

`reader.js` 缓存使用完整原文、读者心理开关、玩家名称及协议修订键；`local-render-cache.js` 的 IndexedDB 命名空间为 tisya-render-cache，存放当前渲染版本的一份有界派生快照，最多 64 项、400 万字符计量预算。新版本不复用旧解析结果；写入失败明确报告，不转写聊天/表单。`display-cache.js` 原内存缓存继续保持完整键与 LRU。缓存不能保证宿主冷启动下载、初始化或其他扩展性能。

新增视口附近 800px 的延迟装饰，保留宿主原几何，避免一次装配全部历史消息。无 IntersectionObserver 的宿主使用已有立即呈现路径；不宣称该环境也有视口优化。

版本导航独立置于消息工具栏之后的最底一行，中间显示当前版/总数；无多候选时整行省略，候选端点与生成期间继续禁用相应切换。


## alpha31.12 候选管理

消息底部编号打开完整下拉列表，可直接 1→11；切换调用原生 swipe(forceSwipeId, forceDuration:0)，删除调用 deleteSwipe，编辑调用 messageEdit。前两者的持久化由宿主完成，扩展不重复保存。删除需要确认且保留最后一版；全局生成锁与原生可切换条件仍有效。较早楼层的重骰/切换仍先创建原生分支。高级修改始终抓取当前候选正文，全文润色用独立方形勾选项。

显示修复仅容错 memory 后 actions 开标签中误转义的双引号；不修正文、不回写聊天、不放宽变量和记忆结算。附属解析失败隔离到附属区域，不退回展示原始整条协议。

## alpha31.16 · 长按形式与本轮要求留存

长按仍在触点附近召唤菜单，平时不常驻；视觉复用现有圆框与SVG，菜单为四列快捷项。默认复制本段／选段修改／重骰／更多；用户已保存的旧顺序不覆盖。更多可直接选继续、版本、手工编辑、分支、删除与回溯，并配置直接显示哪些项。原消息快捷栏与候选导航继续保留。窄屏及缩放使用visualViewport边界；点击外侧/Escape关闭，滚动取消未完成的长按。滚动条外观隐藏，滚动功能与输入框保留。

本轮要求不再有第二个发送按钮。默认随剧情发送；独立交流模式仍走同一主发送键，下方RP草稿不动。要求框Enter保持换行。两个通道沿现有连接和生成链路，未引入额外自动模型请求。

唯一已发送要求真源：原生user消息的`extra.缇斯亚本轮要求`，可省略；有值必须是`{format:"tisya.turn-direction/1",text:string}`。只由communication控制器绑定到本次新增且文本核同的用户消息，并调用宿主getContext().saveChat（实际对应saveChatConditional，包含群聊）保存；其他extra字段保留。删除/复制分支随宿主消息生命周期，不靠楼层索引另建要求库。chatMetadata旧feedback是历史采样证据，不充当重骰真源；本版不会凭旧索引自动猜配历史要求。

发送请求保持原生RP不改，另附系统边界说明和`tisya.turn-direction/1` JSON要求块；说明区分角色行动/对白与契约者场外指令，不把要求变成角色行动或长期偏好。JSON转义保护用户输入中的引号、换行和标记。原要求绑定完成后清空草稿；停止/失败/空输出恢复。重复工具回合不重复追加同一要求块。

重骰、重写和同条续写只读取当前末条user消息的已保存要求；不读取下一轮未发送草稿。新normal输入不携带旧要求。保存失效、原消息被删/改变或协议损坏时停止该发送，UI仍保留。消息下“本轮场外要求”可展开查看原要求，与正文分开显示。

验证：单元与生产挂载测试覆盖重载、原生分支副本、删除、重骰/续写、新轮不继承、失败恢复、保存中停止、字面注入与重复请求去重。未付费调用模型来验证语义遵守；Android及真实WebView视觉仍待实测。浏览器渲染检查因本环境Chromium下载返回损坏归档未能运行，不能算视觉通过。
