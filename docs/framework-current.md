# 当前框架与唯一实现

模型只填写业务表格。任务选择、字段定义、身份分配、授权、版本、补读、应用顺序和存档均由插件处理。

| 共同职责 | 唯一源码 | 实际消费者 |
| --- | --- | --- |
| 分组、行号、字段名、单次文字解码、原文块 | `tables/foundation/form-text.js` | 基础表单引擎、归档、创世、基点提取、基点对应表 |
| 定义来源与本次事件来源边界 | `tables/source-text.js` | 归档、初始化、创世、基点提取及保存校验 |
| 不可变能力登记、唯一身份、显式查找 | `services/capabilities.js` | 辅助任务、状态操作、设置导航、行动输入 |
| 任务入口、专属授权、请求准备和返回解析 | 能力所属 `compact-fill.js`、`simple-genesis.js`、`simple-core.js`、`structured-tasks.js`；`task-registry.js` 汇总 | 11 类任务的预设、模式、助手、业务调用及请求审计；模式/名称/分类均派生 |
| 状态定义、四种手动操作及事件结算入口 | `tables/state-service.js` | 状态页面、创世使用的原数值契约；四种预览入口由同一操作登记生成 |
| 预览凭据、上下文与档案版本绑定、容量及释放 | `tables/preview-store.js` | 状态填表、条件动作、档案提炼、档案恢复；保留各自容量和专属校验 |
| 设置显示信息、分组、离页要求和路由 | `settings-navigation.js` | 29 项设置入口与实际点击分派；额外原生抽屉保持原宿主所有者 |
| 行动模式说明、输入合成和直发资格 | `actions.js` | 行动菜单与执行共用三种登记；草稿和命令符保护保留 |
| 可取消、有字节上限的严格 UTF-8 读取 | `config/response-reader.js` | 普通缓冲响应、正文工具流 |
| 传输错误编码 | `config/transport-error.js` | 统一传输、缓冲响应、正文工具流 |
| 文档所属元素创建、字面文本显示 | `ui/dom.js` | 配置面板、归档面板、助手、动作、输入快捷键等 12 处 |
| 背景特效字段、默认值和选择逻辑 | `vendor/shared/chat-effects-options.cjs` | 生成的单一 `chat-effects-core.js`，由设置与视觉模块共同引用 |

入口描述与执行策略归同一能力模块；UI 从登记取描述并调用该模块。公共调度不再按任务名分支挑解析器，新增任务必须提供完整入口与执行契约。未知能力、重复标识、缺策略显式拒绝。

共享层只做共同职责。表格解析不写存档，文本读取不重试或解释协议，DOM 工具不持有全局文档；来源与权限依然由业务入口核验。不同任务的数据和授权规则不合并成万能服务。

## 当前表格协议

使用 `【类别：完整名称】` 和 `行号 字段名：值`；关联抄提供的 `类别／名称`。宿主内部的表 ID、记录 ID、版本和提交操作不成为模型填写内容。

多行原文使用 `|` 与每行两个空格缩进，或完整双引号字符串；只解码一次。原文中的标题、引号、CRLF、反斜线和边缘空格保留。空白表示不改，明确清除填“清空字段”；误登记撤回填“处理方式：撤销”。明确新记录填“新建”，同名时停止核对。薄档先通过完成组申请补读，再重新交付完整提案。

初始化、对象建立、历史补录、记忆归档、创世、基点提取/适配均不接受旧 JSON 操作提案。旧 Markdown 双列表、隐式多行续写和内部多段标题已删除。仍有专属结构化契约的规则校对、原生变量、剧情推进、偏好分析、配置助手不是这些表格任务的备用入口。

已保存的用户数据和旧回复读回解析继续保留其独立兼容边界；删除旧生成入口不等于删除已有档案。原卡、来源材料、失败首答和许可证不改写。

## 构建与核验

- `npm test` 检查实际插件、基础表单预览及其他生成文件与源码一致，再执行全量回归。
- 插件构建检查真实依赖图，循环依赖直接失败。
- 设置与视觉构建按原 provenance 的逻辑路径核验共享原始文件的哈希；两个原位置仅留来源映射，不保留第二份源码或运行时定义。
- 可编辑源码、必要生成产物与历史恢复材料有不同用途，不把历史快照纳入当前运行入口，也不手改生成文件。

这些检查证明本次自动化范围内的结构与行为，不替代原始百轮资料的独立语义检查和 Android 实机验证。原始失败回答仍保持原样，发布门槛没有降低。

## 全功能职责复核

| 功能域 | 共同实现与保留边界 |
| --- | --- |
| 原卡初始化、对象建档、补录、归档、创世、基点提取/适配 | 共用任务登记、请求进度与表格基础；各自来源、模板、用户原文、旧进度与适配映射校验保留 |
| 状态、公式、成长、事件、条件门禁/动作 | 数字等级与世界名称/公式仍按原注册表；预览生命周期共用，事件参与者、成本、抽签、冷却、知识权限和跨分支回执各归原规则 |
| 原点/会话档案、图鉴、恢复、时间锚与平行分支 | 共用书籍网关、账本投影、查询授权；恢复仅空目标、锚点继承和原著冻结保留，不能统一成覆盖式保存 |
| 原生变量与本插件状态 | 继续通过原生桥与独立所有者结算；相同数值不代表可以共享余额、生命周期或写入者 |
| 配置、任务路由、原生资源 | 现有注册表、编译器和宿主适配器共用；用户覆盖、继承、原生引用及外部写入回执不扁平化为同一数据仓 |
| 设置、助手、行动、消息与输入界面 | 设置和动作入口登记驱动；面板生命周期、DOM、安全显示和资源解析继续共用；消息重骰/分支/历史删除的专属时序与确认保持 |
| 流式传输、工具回合、普通响应 | 共用传输错误和受限读取；正文流与工具协议各自状态机、取消和恢复语义保留 |
| 阅读渲染、特效、主题、字体与缓存 | 现有同源构建和显示缓存服务复用；布局、原生展示来源、可见范围与缓存事务职责分开 |

统一的是可复用的机制与调用契约。预览框架不替业务作出授权，不提前抽签或扣费；确认仍先检查持久回执、当前分支及各领域依赖。创世两本书的部分写入、原生宿主结算等边界不能靠换成一个函数就冒称原子事务。档案草案会话的工具预算/取消资源与创世来源封印仍是独立生命周期，不并入纯预览票据。

旧 `task-kinds.js`、`task-profiles.js` 的平行定义已删除；公共导出是登记投影，不是另一份可编辑配置。旧消费者全部切换，审计工具也使用生产登记的准备流程。没有迁移已存数据、简化专有能力或新增静默备用通路。
