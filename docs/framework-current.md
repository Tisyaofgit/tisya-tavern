# 当前框架与唯一实现

模型只填写业务表格。任务选择、字段定义、身份分配、授权、版本、补读、应用顺序和存档均由插件处理。

| 共同职责 | 唯一源码 | 实际消费者 |
| --- | --- | --- |
| 分组、行号、字段名、单次文字解码、原文块 | `tables/foundation/form-text.js` | 基础表单引擎、归档、创世、基点提取、基点对应表 |
| 定义来源与本次事件来源边界 | `tables/source-text.js` | 归档、初始化、创世、基点提取及保存校验 |
| 六类模型表格任务的分类 | `tables/task-kinds.js` | 任务预设、模式入口、业务服务、归档解析 |
| 可取消、有字节上限的严格 UTF-8 读取 | `config/response-reader.js` | 普通缓冲响应、正文工具流 |
| 传输错误编码 | `config/transport-error.js` | 统一传输、缓冲响应、正文工具流 |
| 文档所属元素创建、字面文本显示 | `ui/dom.js` | 配置面板、归档面板、助手、动作、输入快捷键等 12 处 |
| 背景特效字段、默认值和选择逻辑 | `vendor/shared/chat-effects-options.cjs` | 生成的单一 `chat-effects-core.js`，由设置与视觉模块共同引用 |

共享层只做共同职责。表格解析不写存档，文本读取不重试或解释协议，DOM 工具不持有全局文档；来源与权限依然由业务入口核验。不同任务的数据和授权规则不合并成万能服务。

## 当前表格协议

使用 `【类别：完整名称】` 和 `行号 字段名：值`；关联抄提供的 `类别／名称`。宿主内部的表 ID、记录 ID、版本和提交操作不成为模型填写内容。

多行原文使用 `|` 与每行两个空格缩进，或完整双引号字符串；只解码一次。原文中的标题、引号、CRLF、反斜线和边缘空格保留。空白表示不改，明确清除填“清空字段”；误登记撤回填“处理方式：撤销”。明确新记录填“新建”，同名时停止核对。薄档先通过完成组申请补读，再重新交付完整提案。

初始化、对象建立、历史补录、记忆归档、创世、基点提取/适配均不接受旧 JSON 操作提案。旧 Markdown 双列表、隐式多行续写和内部多段标题已删除。仍有专属结构化契约的规则校对、原生变量、剧情推进、偏好分析、配置助手不是这些表格任务的备用入口。

已保存的用户数据和旧回复读回解析继续保留其独立兼容边界；删除旧生成入口不等于删除已有档案。原卡、来源材料、失败首答和许可证不改写。

## 构建与核验

- `npm test` 检查实际插件、基础表单预览及其他生成文件与源码一致，再执行全量回归。
- 插件构建检查真实依赖图，循环依赖直接失败。
- 设置与视觉构建按原 provenance 的逻辑路径核验共享原始文件的哈希；两个原位置仅留来源映射，不保留第二份源码或运行时定义。
- 可编辑源码、必要生成产物与历史恢复材料有不同用途，不把历史快照纳入当前运行入口，也不手改生成文件。

这些检查证明本次自动化范围内的结构与行为，不替代原始百轮资料的独立语义检查和 Android 实机验证。原始失败回答仍保持原样，发布门槛没有降低。
