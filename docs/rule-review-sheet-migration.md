# 原卡规则校对简表迁移（前一阶段记录）

后续全部 TABLE 任务接线状态见 [table-task-sheet-migration.md](table-task-sheet-migration.md)。以下保留规则校对最先闭合时的范围与实现记录。

本次只迁移 `ruleReview` 的模型输出协议。模型收到中文分组简表规范，返回简表文本；程序解析为既有 `tisya.rule-review-proposal/2` 内部对象，再执行原文来源、行号、引用范围、改动冲突等原校验。通过后才保存校对草稿，用户逐题选择后才影响后续初始化。没有修改角色卡原文。

这不是全部辅助任务已完成迁移：`ruleReview` 输入仍使用现有资料槽与序列化，包含 JSON 元数据。其他辅助任务仍使用原协议。HTTP 请求和内部存储对象继续使用 JSON；二阶段统一归档、世界推演、检索与正文偏好的整体装配尚未在此变更中实现。

## 实现入口

- `tables/rule-review-sheet.js`：规范、严格简表解析、测试样本导出。
- `tables/prompts.js`、`tables/modes.js`：仅规则校对切换输出规范；任务开场、流程、提交提醒和末尾触发句一致，不再要求本任务输出 JSON。
- `tables/service.js`：本任务的模型文本只走简表解析，随后继续原来的校验、保存与选择链。
- `tests/rule-review-sheet.test.js`、`tests/rule-review.test.js`：解析边界与实际服务保存/选择/初始化联动。

分组标题、稳定数字、字段名和值沿用已有简表方向。本次新增嵌套编号分组、明确数量格和两空格续行扩展，并非此前已经存在的通用极简归档协议。完整模型规范以 `ruleReviewSheetInstructions()` 为唯一来源。

无问题的完整回答：

```text
【校对】
1 问题数量：0
```

有问题时按数量展开 `【问题／1】`、`【问题／1／原文／1】`、`【问题／1／方案／1】` 与 `【问题／1／方案／1／改动／1】`。程序生成内部问题/方案 ID。引用使用提供的来源 ID 和原文行号；不要求模型重复抄写旧原文。修改后文本支持两空格续行，保留文本空白；续行换行统一 LF，原文定位仍基于原始资料。

## 失败及兼容边界

模型返回 JSON 字符串、缺行、重复项、未知分组、数量不一致或无效引用均报错，不自动重发、不降级 JSON、不覆盖已保存校对。网络响应外壳中的文本先抽取后执行同样解析。已有保存对象与内部执行器仍经原领域校验读取，兼容路径不代表新模型文本接受旧协议。

此次只涉及规则文字、来源与行号，未建立通用变量值、任意嵌套类型、ACL 或偏好写入的简表 codec；这些不得套用本格式绕过现有验证。没有实接模型生成测评，不声称模型格式错误率已归零。
