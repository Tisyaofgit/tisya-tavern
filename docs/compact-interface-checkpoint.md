# 紧凑界面、简表协议与装配层 · 候选断点

本轮基于 `cbbd4f1fa5618ec777a65c911ae8f910fd2b7d02`，保留正式 main 的全局游玩偏好修复。本文件记录候选实现，不代表 Android、真实模型或新装配方案已经验收。

## 用户确认的方向

- 静态图鉴为稳定档案的增量修订；当前快照为实时状态；历史事件仅放已发生事实。只读档案尽量直接展示，编辑时才进入表单。
- 设置和复杂字段同层导航、唯一主入口、左上返回；返回与切卡不丢当前会话草稿。初始化规则逐题选择，任务阶段/耗时/流式原答可见。
- 玩家角色绑定当前卡与聊天，不改全局默认；新卡提示创建或选择，新聊天提示沿用或更换。
- 内置自然语言规则可修改/恢复；人物、场景和内心段落用自然叙述承接，不强制方括号标题。
- 默认目标为两段请求：A 已确认记忆归档＋世界推演＋档案检索；B 本轮偏好分析＋结合已确认长期偏好的正文。独立 API 用户手动开启。未确认最新回复不入历史，重骰不重复结算。
- 全部相关模型任务迁移至极简填写；内部存储/HTTP JSON不变。沿用现有 compact-v2 分组、稳定行号、字段名和值，不把复杂 JSON 塞入一格。
- 成功归档的旧正文退出历史窗口；正文使用结构化资料、条件触发内容和必要最新原文。原书对应条目由存档书接管，须保留来源映射、作用域、触发与条件语义，禁止重复注入或提前全书关闭。

## 已完成候选的边界

界面、提示词、身份和规则校对迁移的具体测试见 ui-evidence。手动人物提炼原已接通 compact-v2；规则校对在本轮接入简表输出，程序恢复原内部结构并复用严格验证。其他任务尚未全量迁移，不能把存在简表解析器称为全局生效。

曾评估过单一正文请求承担全部维护，用户澄清后该实验及所有接线已撤回。两阶段合并方案仍是设计，当前运行链保持既有规则；不得以关闭任务或只让多个任务共用接口冒充请求次数减少。

## 后续必须闭合

1. 将归档、对象建档、世界推演、偏好、初始化模板、创世、助手、状态/条件及工具任务逐一接入任务专属简表；失败保留原答，不自动重发或静默改用旧 JSON。
2. 两阶段调用事务与重骰/分支/中止恢复；读取工具若需额外模型轮次必须明确另计。
3. 逐条原书来源映射与替代、条件引擎接入资料装配、按已确认归档来源过滤历史正文。
4. 用户审阅完整装配 TXT 后修改预设；隔离真实模型格式与 Android 几何/交互验收仍待做。

没有修改用户设备、运行真实付费模型或删除用户世界书。删除修复仅以隔离存档测试。
