# alpha30 · 缇斯亚助手与第二组十轮归档实测

本轮完成配置助手运行、十轮连续归档与必要修复。完整回归 339 项通过。基线为 alpha29（`6b2d25dc37acffa5519c5eb9119b5233dfe752ac`），正式 r243 不变；尚未扩展完整剧情推进引擎。

## 实际怎么测的

每轮开启无父对话历史的模型任务，只提供当前生产代码编译出的完整预设、该轮来源及上一轮已提交的表格。全部输入分块完整读取，并在答复前后校验收据。模型生成的原始 JSON 再经过真实解析、字段校验、归档服务和存储提交；没有用手写答案冒充模型生成。

十轮按顺序连续提交，全部一次通过格式与提交校验，每轮只增加一份事件摘要，最终待处理为 0。测试过程中发现语义缺口并修改提示词，因此这是“连续排错测试链”，不是十轮完全同版本提示词的稳定性证明。原始各轮请求和答案均保留，未重写成修复后的结果：第 2 轮暴露的位置失效问题另开隔离实例复测；新字段和规则随后进入后续轮次。最后又独立复测了任务来源与随身物品定位。

模型共实际运行 13 次：10 次连续归档、1 次配置助手、2 次针对性复测。宿主世界书接口使用本地内存适配器，助手按钮由 happy-dom 执行实际页面处理函数；这不等于用户手机、真实供应商 API 或已安装数据库扩展组合的实机验收。

## 助手实测

用户目标为保留 15 条历史、使用原生上下文、开启归档、关闭剧情与偏好分析、继承主 API、消息快捷栏只留下一条和更多，并安排旧楼层补录；缺少的船舶载重与航线模板交给创世。

模型只提出 3 项实际差异：历史条数 50→15、开启表单总开关、修改消息快捷栏。已经符合要求的设置没有重写。先显示改前改后，点击应用后才保存；原卡世界书和数据库资料绑定均保留。后续补录成功建立原点书和会话存档，只归档旧 AI 楼层，最新层继续暂存，创世需求仍可继续操作。

修复前，点击“应用全部更改”会清掉补录与创世按钮；修复后更新建议的配置版本并保留操作。外部配置或会话变更仍会阻止应用旧建议；补录有待处理项时不会再提示全部完成。助手未自动创建不存在的模板，也没有声称已经生成蓝图。

## 本轮补上的缺口

1. **状态有效性**：新增可选枚举“有效／失效／待确认”，兼容旧模板。旧位置失效但新去向不明时保留最后已知；到期但结果不明时不编造交接或完成。
2. **中文剧情日期**：明确的公历中文日期可参与到期比较；不使用设备时间，不推断不完整日期或虚构纪年。
3. **历史事件注入**：人物引用不再让全部参演事件强制进入上下文；明确事件引用、关联线索及关键词／向量命中仍可取回。
4. **任务来源与物品定位**：业务“来源”不再复制系统哈希；随身位置通过保管者或容器关联，独立安置位置才填地点。独立复测输出“双方借款约定”，随身箱子未重复填写携带者地点。先前链条已写入的旧哈希仍原样保留，未冒充全部历史数据已迁移。
5. **助手操作衔接**：保存设置后仍能继续补录和交给创世，不丢建议，也不绕过版本检查。

同一最终快照、同一查询“铜铃为何借调”、只引用叶舟时：原逻辑强制带入 10 条事件，修复后强制事件为 0，查询取回 1 条。候选蓝灯事件文本从 4799 字符降为 555 字符；这里统计的是候选文本，未把它说成宿主最终 token 数。

## 还需要什么

这组归档情境没有要求新增独立业务表，缺口主要在状态有效性及字段职责。12 张基础表已经容纳对象、事实、场景、状态、关系、认知、物品、事务、时间、线索、事件和偏好；仍允许创世扩展嵌套字段、类型和表。

后续推进引擎值得补两项：任务的结构化计量进度（如目标量、已完成量、单位，供公式计算），以及发现环境／日程的可执行条件与重复触发状态。应在既有事务和状态体系中扩展，避免新建第二份余额或事件账本。本轮只保存有依据的发现环境，没有实现“到同地点自动刷出人物”，也没有启动离场世界模拟。
