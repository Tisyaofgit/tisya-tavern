# Vertex 流式抗截断（AT01 · alpha31.2）

在“预设与 API”的通用、模式或任务路由中，选择“抗截断传输 → Vertex 流式抗截断”。默认关闭，任务可明确选择关闭以覆盖上层开启。最近一次适用情况和实际包装信息显示在“上下文一览”。

功能把整篇正文放入一个仅用于传输文字的函数参数，并在接收时逐段还原。没有工具执行、工具结果回传、自动重试或自动续写；一次生成只调用上游一次。用户主动点击继续或重骰仍是各自的新请求。原生 continue 只要求新增后缀；缇斯亚“下一条”仍遵循已有独立语义。

本期限定原生 Vertex 的 Gemini 3/4 纯文字请求，不含 Flash-Lite、图像模型、代理、搜索、多候选、结构化输出、真实工具或工具历史。其他请求保留原行为，并在快照中说明未启用原因。Unicode 和图片转码未接入。此列表是代码接入范围，尚非真实模型效果保证。

正文实时出现，只有响应完整结束后才放行成功状态及缇斯亚自动归档。长度上限、过滤、断流、损坏尾帧、HTTP 错误、停止或上下文变化均不自动补发请求。停止保留已显示的片段；片段不当作完整结果自动归档。本功能不能突破模型 token 上限，也不保证解决所有截断。

若安装了社区抗截断插件，请只启用一个实现并重启。发生请求通道冲突会明确失败。连接凭据与服务商请求由 TauriTavern 原通道处理，本功能不新增代理服务或密钥配置。输入包装及工具声明计入本功能的文本预算检查，仍会增加少量输入成本。

## 实现与验证边界

- 入口：`config/vertex-transport.js`；宿主接线：`config/host.js`、`index.js`；路由与界面：`config/core.js`、`config/panel.js`。
- 社区来源固定为 ken050210/vertex-streaming-anti-truncation 提交 `e9603b2c9d81f7d683801ca12b9f95e10a5a8732`。七个解码／协议模块原样保留，MIT 与来源声明见 `vendor/vertex-transport/`。
- 执行 `npm ci` 后运行 `npm test`；专项为 `node --test tests/vertex-transport.test.js`。本地夹具覆盖真实配置面板与 createHost 接线、流式/缓冲格式、单次调用计数、停止/切换、尾部校验及防重放；不等于真实模型或 Android 验收。
- alpha31.2 基于已发布 main 的 alpha31.1 单独接入本功能。开发候选中的 KB01 工具循环、C01 等其他改动不随本次发布。关闭或不适用时，保留 alpha31.1 的辅助 API 返回对象与非流式行为；抗截断启用后才使用新增响应校验器。
- 下一验收阶段：真实宿主下的 Vertex 长文开关对照，以及 Android 的显示、停止、切屏和存档检查；这些尚未运行。
