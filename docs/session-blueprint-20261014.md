### KB01-N1 · 并行工具调用与请求计数须知（2026-10-15）

“并行算一条”准确指：**同一条模型响应内同时给出多个工具调用，仍只对应一次模型请求；不按其中的工具数量增加模型请求次数。** 本地执行这些工具后，将结果合并回填、再让模型续答，会新增一次模型请求。多个独立HTTP请求即使同时发出，也必须分别计入请求预算，不能因为并发而合成一次。

- 实测：Powerbox的`[0.4刀/次]gemini-3-flash`线路，一轮返回3个独立查询调用，统一回填后给出最终答案，全流程为2次HTTP模型请求；两次各扣200000原始quota，数据台对应各0.4站内显示单位。OpenAI聊天格式与Gemini原生非流式格式均跑通；响应自报`gemini-3.8-flash`不作为底层身份鉴定。
- 顺序依赖：必须先读上一工具结果才能决定下一工具参数时，按实际续轮分别请求。量卡`gemini-3.8-flash`实测3步依赖工具加最终回答共4次模型请求；不能把整段工具循环视为一次请求或一次缓存命中。
- 设计应用：相互独立、已获本轮读取权限且满足同一快照与预算的查询，优先让模型同轮给出、宿主收齐结果后统一回填；依赖查询保持顺序。保留调用ID/原生签名及结果配对，仍执行既有批量上限、取消、过期和人物知情检查。本条不声称现有实现已具备并行执行调度。
- 适用边界：这是上述中转线路、套餐和非流式小样本的计数观察，不推广为所有供应商的计费保证；工具自身外部服务费用另计。量卡按每次实际token计费，本轮重复请求未观察到缓存折扣；缓存即使命中也不将多个HTTP请求合并成一个。流式兼容、缇斯亚实际工具集成和Android仍需各自验收。

证据：`Powerbox__实测证据__0.4次卡工具与多模态-20261015.zip`（稳定ID `libfile_f7cb7adb06e48191ae017369bbb0d82c`，版本1）中的`02_parallel_calls/final`、`07_native_tools/final`；逐步调用对照为`Powerbox__实测证据__3.8量卡逐步调用与缓存-20261015.zip`（稳定ID `libfile_781a4f7b11cc8191aaff5be2504405bb`，版本0）。本条仅记录既有实测，未新增付费调用。

## 两条完整流程

### 资产随卡适配

用户选择人物、装备及其他对象 → 检查关联闭包并列明会带入什么 → 提取／复用基点版本 → 用户补充和修改 → 按目标卡形成适配蓝图 → 对照每条核心、叙事意义和物件关联 → 用户确认后写入该卡原点 → 独立建立当前 U 与队友开局档案 → 才开始剧情。

原卡规则有问题仍沿用既定红色提示及“保留并静默／选择优化方案”流程；不能借适配静默优化。全局已确认偏好用于新创作的原点设计，用户指定细节保留。原创人物逐对检查动机、关键选择、代价、信念、关系模式和习惯，避免换皮复制。用户在过程中新输入的对象与偏好同样进入草稿确认流程。

### 完成存档成为原著后换 U

选定原著存档版本 → 选择分歧时间锚 → 列出锚点前已成立状态和锚点后原著事件 → 绑定新 U 并预览受影响的身份／关系／持有 → 确认分支 → 每次推进检查原著时间与因果条件 → 未改变条件的事件按原定顺序和时机发生 → 有干预证据的事件及其依赖按因果改变 → 结果只写新存档。

“换 U”不等于把旧 U 的姓名改掉后继承全部爱情、认知和背包。角色代入需明确选原著角色位或作为新角色进入；实际开局界面必须让用户看到身份映射和起点差异。两种入口都保留，但不替用户默选未知的角色替换方式。

## 原著运行的判定要求

1. 原著节点保留稳定编号、原文来源、原著版本、剧情时点／区间、前置条件、参与对象、具体结果和后继依赖。来源仅给先后顺序时就保留顺序，不伪造日历。
2. 条件保持时，原著事件是应发生事件。U 未看见、离开现场或没有主动点选，不使事件消失；应发生的场外事件仍推进。发生后才写当前分支事实。
3. 不能为了戏剧性随意改变原著，也不能为了强推原著忽略干预。改变必须记录“哪次行动或设定差异→改变什么前提→影响哪些节点”。救走关键人物只改变相关因果，远处不相关事件照常。
4. 条件不明或旧存档缺原文的节点保留核对状态，不能偷偷跳过后称为遵循原著。明确缺项，允许用户补充；有确定来源的独立节点继续按原著推进。
5. 原著中的对白、亲密关系与旧 U 行动不机械套给新 U。角色位替换本身可能改变事件前提；受影响范围在分支预览中列明。未受影响的世界事件继续必然发生。
6. 玩家可以看原著不代表角色预知。未来原著、隐藏真相、原著角色认知与当前 U 所知分别供给；昵称、暗语、承诺的反应只来自当前分支已成立经历或明确开局继承。
7. 时间锚之前的状态只由该时点的版本和已成立变动重建。之后的成长、关系、伤势、获知和物品流转不能倒灌。后续人物可作为未来资产存在于原著资料层，不等于当前已登场或相识。
8. 重骰保留 n/N 与旧候选。切换候选重算当前分支事实及原著节点的已执行／分歧状态，不能重复执行事件或让被撤回的干预继续影响未来。
9. 现实保存时间仅用于版本审计，不用设备日期填剧情时间。“三天后／当晚”只相对已知剧情锚解析；未知日期明确保留。
