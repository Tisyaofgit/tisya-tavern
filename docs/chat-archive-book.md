# 聊天自动存档书

版本：candidate.38-archive.1。

打开聊天后，既有自动接入流程为该聊天建立一份独立的原生世界书，并在聊天元数据 `tisya_engine.archive_book` 保存绑定。旧聊天首次打开时补建，重复打开复用同一本；复制分支得到自己的聊天 UID 和书名。原生剧情书的 `world_info` 绑定保持原用途。

书名由聊天名和完整聊天 UID 组成。`表单与存档` 显示本聊天的书名、同步状态和重试入口。

实时数据仍归既有 IndexedDB 数据库；存档书是同一数据库提交后的完整 JSON 检查点，包括表结构、业务状态、回合日志、人工变更、确认和回退资料。保存通过同一 storage commit 边界接入，未新增另一套可独立编辑的业务账本。完整存档条目关闭激活，原生扫描也排除本书和归档标记条目。用户另外添加的条目及书籍元数据在更新时保留。

同步按聊天书独立排队，取队列执行时最新的本地版本，写入前检查原书、写入后重新读取服务器内容核对版本和摘要。本地已提交而原生保存失败时，明确显示“本地存档已保留，存档书尚未同步”，保留具体错误和提交回执。重试只补齐接入和检查点，不重放回合、奖励或消耗；首次失败也通过原自动接入服务的显式重试恢复。

本功能保存到当前宿主的原生世界书，不提供跨设备自动同步，也不会在本地数据库缺失时擅自以空状态替换。真实 TauriTavern/Android 的文件容量、保存耗时和组合扩展仍需设备验证。

恢复来源为已发布 main `8ee53bc64671021416f01fd732e1cfe1c510c40e`。用户截图所述 `candidate.37-forms.1` 尚未在远端分支、当前项目蓝图或本次可用工作区找到可恢复源码；本提交仅加入本轮自动存档书，不声称包含该未取回候选的表单优化。

验证入口：`tests/chat-archive-book.test.js`、`tests/default-activation.test.js`、`tests/shell.test.js` 和 `tests/browser-chat-archive.html`。浏览器页使用正式 host、配置 UI、原生适配器和真实 IndexedDB；原生世界书后端为隔离模拟，不代表真实宿主验收。
