# W34 自动初始化、开局建立及历史补档恢复

## 问题与修复

W33 的初始化把手填资料提炼当作完整初始化，只要求 source 文本；历史补录也只有粘贴路径，开局建立缺少独立服务与入口。旧测试的手填成功并不证明原有自动业务仍在。本次恢复原生角色卡/内嵌书/角色主附世界书读源，初始化只保存确认底档，开局按已采用的开场、人设和指纹一致的定义建立，历史按选定原生楼层顺序补档。

读源失败、过期草稿和存档失败保持可见。使用同一 B 账本与原生原文库，保留用户身份和原文引用；没有重置聊天或世界书。手工补充仍显式可选，不能充作自动失败后的兜底。

## 验证范围

- 实际原生书籍适配器：主/附角色书限定、停用过滤、读取不写、来源修改及缺失报错。
- 实际应用服务和 UI 点击：不粘贴自动初始化→确认底档→所选开局与原生 user→书内独有初值→两楼历史→当前状态6到5→原文引用→冷重开→下一次正常 A/B 发送；已有楼层不重复归档。
- 实际 configHost.request 装配：definition/opening 阶段、卡/书/补充、模板、所选开局均进入实际请求；旧无phase任务保持原合同。
- 原点定义保存及重读保留来源凭据；混合定义版本拒绝；候选不可伪造原文、跨身份或覆盖后续状态；存储失败可恢复同一草案。
- W33 发送/元数据顺序、偏好及草稿保留回归继续覆盖。

宿主 JS 为实际提取源码；HTTP存储、模型回复和 DOM 是明确测试夹具。未做 Android、外部模型语义验收。世界书模块手机现场加载根因没有新证据，未标解决。
