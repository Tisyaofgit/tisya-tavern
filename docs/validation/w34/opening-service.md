# W34 开局建立后端核验

已有 V3 仅把初始化路由到 extract；没有单独的开局生成和确认入口。新增 opening-service 复用已登记 templateInit 的 phase=opening，采用已确认绑定定义或已保存初始化提交，读取当前实际开场和原生用户人设。若聊天已采用开场，不将卡上其他备选开场作为可选事实源；聊天为空时卡上候选明确标注尚未写入聊天。此任务不写聊天正文。

原生 user 身份和描述由程序按原文生成受保护行；模型只引用 objectId，并为有独立定义的队友和其他对象提出档案。用户身份映射来自同一账本 openingEstablishment.player 回执，按当前 persona 及保留提交解析，不新增独立元数据真源。根组件负责将此映射接入后续叙事。

生成、预览不提交。确认保存追加 kind=init 提交，禁止覆盖已确认字段、删除、伪造历史事件、原生变量和偏好写入。来源、模板、用户、绑定、账本版本变化均拒绝过期草稿；写后回执丢失可重试同一冻结提交，不重跑模型或重复新增用户。

验证：opening-service.tap 的 15 项服务测试通过，覆盖真实简表解析、复用既有 ledger 投影/提交实现、来源选择与失效、原生用户保护、回执恢复、重新实例化、错误产物和取消。模型回复为确定性夹具，未做真实模型或 Android 设备实测。后续实际应用和点击流程由独立集成验收完成。

追加验证：已确认原始角色卡/世界书按有效定义指纹重新读取，原点/基点定义行自身保留 designProvenance（包括 definitionHash 与 sourceSupplement），无需建立第二份原文存储。真实 book-manager 保存/读取原点定义后，书中独有的开局关系仍进入开局请求。定义来自不同源版本时明确停止；不按行序选择一个来源覆盖其他定义。开局确实引用已采用聊天开场时，回执保存 floor=0 与原文 SHA256，供随后原生历史补录建立可核查时序。
