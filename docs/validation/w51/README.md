# W51：原基点可见性与显式工作区恢复

## 已确认问题

待同步记录阻止 books.global/绑定读取，旧 loadBookPage 将失败当成空绑定，显示“尚未选择”及创建按钮，并重复展示相同错误。原生宿主接口夹具保留同一基点和全局指针时，旧 workbench 的新回归按预期失败，页面文本与用户反馈相符。这证明界面误导，不能据此断言用户设备的数据没有发生其他故障。

旧同步按钮只刷新快照，未重载绑定页状态。应用层又将物理同步和随后配置 hydrate 视为一个整体错误，可能将已完成的保存显示为同步失败，或遇到未提交配置草稿。

## 实现

- 用物理存储的只读全局绑定检查展示已保存基点，明确与保留的工作副本区别；不写指针、不清 journal、不以缓存替代配置。
- 读取失败时隐藏创建/切换入口；显示待同步书籍、所属会话和错误码；去重相同错误。
- 同步后重载绑定、书籍与配置；物理保存和配置重载分别返回结果，已有草稿保持原对象，不覆盖重载。
- 同步仍经过原有所有者、并发和条目冲突检查。无待同步时生成中查看世界书仍允许。

## 验证

最终 npm test：1499 根测试和 759 V3 测试全部通过，共 2258。新增五项覆盖：只读恢复检查、实际工作台按钮同步并刷新、跨会话拒写、已保存但配置重载失败、保留配置草稿。相关目标集合 55 项通过。旧 UI 回放按预期失败，失败文本保留于私有诊断。

首次完整回归的两项失败已保留：候选多余 idle 阻止生成中无 pending 的只读世界书访问（已移除并通过相关和全量检查）；恢复的源码检查点遗漏既有中文资产（从原生扩展原件恢复用于测试，未对远端资产做改动）。构建 runtime.js 与当前源码一致。

本轮原生 Linux TT 自动化启动失败于 WebDriver 会话建立超时，未完成应用级点击验证。既有 W49 原生结论仍仅限当时本地确定性模型响应；不得将其当本轮或真实供应商测试。Android 和手机同步失败的精确根因尚未复现。

用户截图同时显示 /v1/models 超时和工作区待同步。截图只证明两者并存，尚不能证明同步按钮触发了模型请求。本轮不更改供应商地址、凭据或过滤策略，不自动重试模型。新增只读恢复和宿主接口回归不访问模型端点。
