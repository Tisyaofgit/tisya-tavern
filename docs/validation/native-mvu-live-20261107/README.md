## 修复及验证

1. 发送新用户楼时，原 MVU 会异步把未变的变量复制到新楼。原适配器把楼号变化也认定为状态过期，实际发送被 NATIVE_MVU_STALE 阻断。改为比对脚本、状态内容与完整注入文字；仍拒绝值或格式变化。新增回归先失败后通过，适配器不调用原生变量写入。
2. 原世界书扫描与矩阵资料槽同时携带同一 MVU 规则及格式。适配器记录实际已消费条目的书名、uid、原内容，仅从本轮原生扫描剔除精确同源副本；其他书、uid、内容及普通条目保留，不改世界书。实际请求同一规则从 2 份降为 1 份；状态块保持 1 份。

原生独立测试卡由原 MVU 初始化 count=0、enabled=false、text=""；收到原 JSONPatch delta 后 count 0→1，原生编辑修正夹具展示格式后仍为 1。正常关闭重启并重新选择测试卡后保持 1；下一轮 37 消息实际请求含真实值 1、规则 1 份，原脚本更新为 2。再由宿主 generate("regenerate") 发起重生成，请求仍取上一楼 1，原脚本结算仍为 2。变量原生更新只发生一次；false 和空字符串保持。

可见聊天区展示正确正文与一个行动按钮，原始更新块保留。聊天首页打开时消息投影延迟，返回聊天并滚动后显示；没有将立即查询的空投影认作产品故障。首次夹具 actions 用嵌套 observe 标签导致 TISYA_V3_REPLY_NESTED_RECORD，已保留原响应并经原生编辑改为合同管道格式；属于测试夹具错误。
