# 世界书模块加载：已验证范围与未解决边界

本次截图的原始错误是 `/scripts/world-info-persistence.js` 动态导入失败。
已上传的 TauriTavern 2.4.0 APK 内确有该模块，且 `world-info.js` 自身静态依赖它；
APK 提取与来源校验见同目录 APK 核验记录。APK 的存在不证明截图设备安装了同一字节，
也不证明设备能够成功请求该资源。因此本次没有把缺文件或版本过旧写成已证根因。

实际修改只集中两处世界书模块加载入口，并保留严格保存协议：

- 公共模块本身给出完整的保存及失败清理接口时直接使用该接口。
- 否则仍要求已验证的 split 模块清理接口；不以加载失败推测旧版或跳过清理。
- 加载失败带中文说明、模块路径、失败阶段、已加载能力名及原始 `cause`，并在任何世界书写入之前停止。
- 没有将写入移动到新存储、没有使用缓存代替磁盘回读，也没有删除用户档案。

旧源码证据 `worldbook-host-history.json` 来自正式上游拆分提交 `dfdd92f25b367158f7574902c0587e9a856fd2bb` 的父版本。
旧单体 `saveWorldInfo` 同样先登记待写文档、失败保留待写状态；仅删除公开缓存仍会在后续 flush 写入候选。
所以没有加入无法证明安全的旧宿主写入兼容。

`worldbook-loading-before.tap` 保留初始候选测试的原始失败，说明对缺 split 模块的合成宿主确能复现截图文字；
该初始测试并非实际 APK 复现，也不是已确认旧宿主协议，后续读到真实旧源后已拒绝其宽松兼容方案。
`worldbook-loading-after.tap` 为最终四项检查：完整公共协议、缺模块诊断、真实提取的 split 保存/回读/失败后 flush、缺清理接口拒绝写入，全部通过。
保存/读取执行真实宿主前端源码，原生字节提交和磁盘为测试夹具；没有执行 Android 真机。

仍未解决：截图设备上模块请求失败的现场原因和实际宿主版本。不能把诊断增强或自动化通过表述为该现场故障已修复。
