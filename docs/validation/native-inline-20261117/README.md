# Native status card fences adjacent to prose

A complete HTML document generated by an enabled display-only regex could touch adjacent story text. The body scanner then missed its opening/closing fence and sent script source through prose formatting. With a second card later in the message, host Markdown could consume that second document inside an unidentified code block, preventing the existing helper-source recovery from claiming either card.

The fix recognizes an entire, single-rule document using its existing body-run provenance. The public AFTER_REGEX hook inserts display-only blank lines around a unique eligible replacement before host Markdown runs. Saved messages and the HTML/script bytes are unchanged. The existing helper remains the only owner of the executable iframe. The prose Markdown-literal lexer is shared without changing its behavior. Literal code examples, numbered literal fences, incomplete/mixed runs, duplicate sources, stale scopes, fragments, reasoning and non-assistant messages retain their previous guards.
