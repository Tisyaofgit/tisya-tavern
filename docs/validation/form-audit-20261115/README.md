# 全字段、引用及模型输入审计 · 2026-11-15

范围：正式 catalog 加手机、态度及偏好编辑器运行时扩展，共 213 张表、3,126 个字段；721 条直接引用、256 项参数绑定、60 项派生定义。全字段清单见 `all-fields.json`，机器检查结果见 `summary.json`。扫描覆盖不等于每个业务场景均已真机验收。

## 已确认问题与修复

| 问题 | 当前行为 |
|---|---|
| 普通模型表单混入存储键、路径、执行处理器、注册规则 | 共用模型字段边界；定位/计算信息留给程序，注册任务才获得注册表字段。内部解析契约保留以兼容旧记录。 |
| 贷款/分期/订单/效果实例等已有执行器结果仍要求模型填写 | 从普通可写表单剔除，实际业务结果继续可读；没有重新让模型算支付、计息、定时或通知。 |
| 手机 LIFE/SUITE 内部状态包装进入资料 | 完整内部表族统一屏蔽；账号、帖子、订单等业务资料按现有知识/会话边界投影。 |
| 关联字段输出数据库编号，手机部分 TEXT 关联没有名称解析 | 显示名称与填表共用同一引用表和现有 phone-form-contract 映射。 |
| 旧约定入口把人物原点直接塞成对象，多方关系直接塞实体 ID 数组 | 复用 T_SYS_ENTITIES、M_FIELD_REFERENCES、M_LIST_VALUES；引用正式人物原点，不另复制人物档。重复接受不增加实体或引用行。 |
| 已有资料、独立引用列表、派生描述和事件梗概重复注入 | 同一已显示记录不再列一遍；有可核验来源的 derived 副本省略；完整事件优先于重复梗概。旧存档只有一份 known 值时保留，不能按只读标签误删。 |
| 偏好编辑器运行时追加字段漏在静态目录之外 | 追加 4 项进入全量审计；选择定位、编辑器类型、启用开关、注入槽位置不交给普通模型填写。偏好原文仍由已有编译入口处理。 |
| 历史 XML 带楼层/来源定位元数据 | 模型 XML 去掉 source/floor/missing 机械属性；内部校验凭据保留。三层模块尚待正式 host 接入。 |

45 项重复投影定义是现有架构清单，不是 45 个新缺陷；大量本来已经由程序持有。7 条非表引用是注册命名空间，不是假报成断链。未发现重名字段键、缺失的实际表引用、参数目标或派生目标。

## 同轮接入的正式代码

- 沿 T_DYN_RELATION_AXES 增补正/负态度、定义、状态标签与定义；正负同时存在，按明确配置的故事时间规则独立增长/衰减，支持范围限制和回退。旧关系类型兼容。
- 正式入口启用人工确认：未确认的 cells/archive 不进入正式库；用户编辑并确认后同事务保存、归档立即正式化。来源/前序变化、重复确认、无效单元格及无效归档均有守卫。
- 重骰期间保留上一已确认状态，重新确认从对应基线替换；本地确认记录随数据库持久化，按楼层撤回并使后续依赖失效。
- 当前生产弹窗已接文本表单编辑、双渠道勾选、确认、已存归档与回退，以及现有全字段编辑器入口。此前 v3 预览中的完整字段选择/常驻规则/历史补录界面尚未整体迁入正式入口。
