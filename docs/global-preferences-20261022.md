# 全局游玩偏好修订与核验

用户确认现象是换角色卡后偏好回到默认，不是模型／预设切换导致丢失。

## 已验证根因与实现

旧 schema 2 以 [角色卡 avatar 或群组 id, chatId] 保存整个世界配置；新的角色卡／聊天没有对应世界条目时，用 defaultWorld 创建只读初值。隔离重现中，A 卡保存 actions=false，换 B 卡后读到 true；期间没有切换模型或预设。

全局偏好现在独立保存在 extensionSettings["缇斯亚配置"].游玩偏好。字段：完整 narrative、summary、actions、workflowDetail、heartDirections、角色主动性、角色对白。读取、辅助任务、当前宏编译共用同一全局值。schema 3 的各世界不再存这组字段的独立副本；schema 2 仍可读取，首次明确保存全局偏好时转换。用户打开页面不会触发转换。可点“将当前偏好全局保存”采用当前旧配置，之后修改游玩及直接叙事偏好自动保存。

主控/角色身份、世界边界、文风资源引用、模式资源、连接路由、MVU和表单原点/会话存档保持各自既有范围，不跨卡复制。schema 3 需要本候选或支持它的后续插件；不静默降回旧格式。备份导入同时支持 /2 和 /3。

保存经宿主确认，版本冲突拒绝覆盖。未填完的语言、保存失败和混合的非偏好草稿保持可见，显式重试。当前会话稳定身份缺失、已观察到的配置突然缺失时不返回初始值覆盖。配置保存后的控件重新绑定，防止后续编辑写入过期对象。

## 验证边界

- 基线复现：已确认换卡采用默认，与模型/预设无关。
- 新增 8 组 Node / happy-dom 用例：自动保存；模型和预设变更后重开；独立 Node 进程从磁盘读取；失败保留与重试；语言输入不完整；缺失保护；混合草稿；新/旧卡、新聊天、群组全局一致与存档隔离；显式迁移；高级叙事和版本冲突。
- 同步修订旧回归中“换世界回初值”的两项预期，为用户新要求的全局共用；其他断言和负例保留。
- 完整回归 1211/1211 与 13 个生成检查通过，发生在最终 schema 3 格式标记及候选版本号调整前；调整后补跑配置/助手相关回归及最终构建校验，见精确回执。
- 未真实模型调用；未在 Android 或用户存档安装。与正在运行的表单全流程候选独立；未覆盖该候选 runtime，也未替换正式分支。

恢复从本修订固定 Git 提交开始，依赖 package-lock.json；执行 npm test。当前候选运行文件 runtime.js 由 tools/build-extension.mjs 完整构建，非局部拼接旧产物。
