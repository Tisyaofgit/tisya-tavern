# 统一正文传输 · alpha31.17

配置只保留继承、关闭和开启。此前四种开启值在路由解析时统一为 universal，不改写用户聊天、模型连接或关闭设置；已退役 vertex-streaming 仍按关闭处理。

## 请求与交付

每个已授权请求只发一次。发送前依据原请求选择处理路径：

- 普通 OpenAI Chat Completions / 自定义 Gemini 文字：增加一个只运输正文的临时函数；原真实函数与历史保留。最终函数参数还原成宿主可读取正文，不执行该临时函数。
- 内置搜索、图片输出、结构化输出、显式工具限制及其他原生协议：保留原请求，用对应协议检查结束状态。搜索保持开启，不再显示“搜索所以跳过抗截断”。
- 上游直接返回完整正文时接纳，并记录 direct；只有成功解码自有函数才记录 wrapped/restored。真实客户端工具为 tool-handoff，交宿主处理，不冒充最终正文。

已有真实函数与内置搜索能否同时使用，仍由宿主及服务商决定。本插件不会删掉任一能力，也不会在失败后改发第二个请求。Gemini 官方支持组合工具，不代表每个中转站都透传其必需配置。

## 响应处理

统一检查 JSON/SSE、完整结束、截断/过滤/空回、取消、超时和结束后异常数据。合成工具恢复后清理会遮住正文的空顶层载体；不把推理或任意工具参数当正文。搜索 grounding、服务器工具记录及真实工具签名保留；合成函数和其签名不回流到宿主执行器。

原生 Gemini、Claude、Cohere 以校验投影处理并把原协议返回主聊天。宿主已经归一化的 OpenAI Responses 复用 Chat Completions 检查。非流 Claude 同时检查可得的原生 stop_reason，不能被归一化的 tool_calls 掩盖截断。未知停止状态不猜成功。

宿主缺少可靠结束证据的协议仍明确报错。例如部分 Bedrock 模型的宿主投影丢失终止原因。Claude 引用数据保留，但旧宿主自己的引用事件解析可能不支持；这里不能替代宿主升级。图片只验证传输载体，不证明图片解码/显示成功。多候选与未知媒体格式不宣称覆盖。

## 验证与限制

本地测试覆盖工具包装、搜索保留、搜索元数据、宿主正文字段、签名、Unicode分片、Claude/Cohere原生流、失败/取消无重试及生产归档门禁。实际 Gemini 3.8 搜索测试、完整回归和发布身份以本次验证记录为准。

已在量卡 Gemini 3.8 的新站点测试“搜索＋函数包装”：三种独立用例均 HTTP400，提示组合工具开关缺失，即使实际线格式包含该开关。服务器内部原因未证实。因此搜索请求预先保留原生路径，不强加本站拒绝的合成函数。首错保留，没有自动重试。

协议完整不保证模型语义上写足所有段落，无法消除服务器长度限制、拦截或网关故障。原生后端/Android完整实机尚未验收，不能把本地宿主函数夹具当作设备通过。

入口：config/text-transport.js；规划：config/universal-transport.js；原生协议：config/native-protocol-guard.js；非流与Gemini响应：config/transport-response.js。第三方vendor模块的许可证与固定来源保留。
