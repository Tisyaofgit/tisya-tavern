# alpha29 记忆归档更新

本次范围是记忆归档、角色卡初始化和可复用原点档案。后续世界推进引擎另行完成。

## 数据保存边界

| 保存位置 | 内容 | 新存档行为 |
| --- | --- | --- |
| 当前角色卡的模板注册表 | 表结构、类型、字段、别名、关联及公式定义 | 可沿用模板，不复制旧会话已填内容 |
| 原点世界书 | 人物、物品、地点、规则等底档的版本，以及发现环境 | 可以选择复用，关联的必需底档一起带入 |
| 会话存档世界书 | 场景、状态、持有、关系、认知、事务、事件和修改时间锚 | 每个会话独立；不会带去新存档 |

发现环境包含地点引用、时段、出现条件、来源依据、确认程度和可复用标志。固定出现规律可保留为原点条件；临时离岗、某日例外和“明日起恢复”留在该存档。一次偶遇不能推定每天必然出现。新存档复用底档不继承其他存档的认识关系或任务完成情况。后续推进引擎可以按这些条件设计相遇，本版只完成记录和检索基础。

## 使用流程

在“表单推进 → 历史补录”选择从角色卡提取模板、使用通用模板或复用已有模板。提取会读取当前角色卡及已启用的绑定世界书定义，显示完整模板、原点底档和当前存档初值；检查后保存，再按实际楼层补录。示例对话与未采用开场不作为历史。

旧回复只有正文也可补录，开场没有 memory 块不会阻塞。手写历史入口保留。自动归档排除最新 AI 回复，避免重投立即写成事实；最新内容仍作为暂存上下文使用。重投或修改来源使依赖它的旧进度失效。

## 表单与提示词

表单按八组展示：世界定义、对象底档、当前状态、关系与归属、认知与信息、事务与日程、事件与修改历史、线索与未解事项。底层保留十二个旧表 ID 兼容已有数据；偏好单独管理。不是把十二张表强行合并为八张。

支持对象、数组、键值表和递归字段校验。新字段先匹配登记名与别名，再按证据扩展类型；新增类型须引用已有父模板。嵌套对象更新保留未修改的子字段，数组按完整新列表保存。共享模板不能悄悄改变旧字段的类型或数值约束；无法判断的部分显示待处理，不伪称整层归档完成。语义上尚未登记的同义类名仍需要模型识别及用户校对，不能声称字符串去重可以保证全部同义词合并。

启用辅助归档后，正文不再重复填写 memory 事件摘要；reply 外层仍兼容，必要的原生变量权限注记保留。历史消息条数仍独立于表单开关，原生变量继续由原卡与宿主执行。

各辅助模式使用完整的头部、输入预处理与路由、资料层、模式处理规则和尾部交付约定。它们沿用缇斯亚身份，只返回任务数据；不填写正文心声，不额外套叙事 reply。实际完整预设和表定义见 [alpha29-presets-and-forms.md](alpha29-presets-and-forms.md)，插件内也可查看。
