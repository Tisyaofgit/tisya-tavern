# 用户消息重投 · alpha31.27

## 入口与行为

- 用户消息使用原有重骰位置，文案“重投下一条”；长按和更多菜单同样路由，不增加重复入口。
- 紧接着是角色回复：调用原生 swipe，原回复及其他候选保留。较早回复先复制到原生分支，原会话后文保留。
- 用户消息处于末尾：用原生 normal/automatic_trigger 生成下一条，不附加“继续”消息，不发送输入框草稿。
- 紧接着是用户/系统/工具消息或未加载楼层时明确拒绝，不能跨过它选取别的回复。
- 高级选段改写、候选切换仍属于角色回复；普通继续保留原来的功能，不偷换为重投。

## 上一版与请求

唯一当前文本仍是原生 chat[i].mes。extra.缇斯亚用户改写 保存版本号、立即上一版原文和当前文本的同步修订指纹，不另存一份可编辑当前文本。指纹仅做陈旧检测，不作为安全哈希。

在原生 MESSAGE_EDITED（正文已更新、保存前）写入；自动保存输入在宿主同步更新后、延迟保存前写入，以整次编辑起点为上一版。已加载记录只建立内存引用，读历史不写盘。取消未保存、无变化保存及输入后撤回都不新增旧稿。二次编辑以最近保存稿为上一版，只保留一份，不累计全历史。

更新之前丢失的旧文不能恢复；未曾观察到原文的编辑不编造上一版。检测到外部改文却未更新修订记录时明确报错，重新保存一次实际编辑后可建立新的可靠上一版。

在用户重投、其后角色回复重骰，以及原生 swipe/regenerate 的聊天补全请求中附加两条消息：固定 system 调整要求和 literal JSON 新旧对照。旧文为已撤回资料，新文为当前有效输入；差异只用于这次节奏/互动/剧情重点调整，不合并两版事件、不凭模糊改动猜偏好、不自动永久记忆。宏串不展开、原预设不改写。真正的叙事改善仍需模型输出与用户评估。

正常发送、继续、辅助任务无此对照。完成、停止、失败、切聊天清理临时请求；生成前核当前消息与所选依据，拒绝迟来的改写。原生自动注入即使漏结束事件，下一次普通发送也清理。

当前对照接入聊天补全后端；其他原生后端明确报告未接入，不能假装提示已发送。无旧稿时仍可普通重投。群聊沿用宿主生成和候选约束，不跨过其他成员回复寻找更早用户消息。

## 验证

自动回归覆盖单次/多次/自动保存/取消/撤回、序列化重载、旧稿缺失与损坏、历史分支、候选保留、失败清理、快捷栏与长按、普通请求隔离、原生和受控两种完整 payload。对照追加之前的全部消息与原装配基线逐条一致。

Chromium 的生产 runtime 配合隔离宿主接口，验证真实点击编辑/保存 → 用户消息重投 → 保留旧候选 → 下一普通请求不带旧稿。宿主脚本依据来自已存目标 APK 对应源文件。没有调用真实模型，没有写入真实用户聊天，Android 实机尚未测。
