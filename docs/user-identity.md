# 用户身份与原点关联

从设置“用户身份”、主页 USER 或当前角色/群聊的“查看／切换身份”进入。设置与子页右上角“聊天 ›”直接回到当前聊天；未保存资料仍有离页保护。

身份档案默认只读，点击“编辑资料”才进入修改。新卡可以“创建此卡专属角色”，真实新建原生身份后只绑定本卡和当前聊天，旧身份资料与全局默认保留。已有原点按世界书、对象ID及版本选择；“创建独立身份并绑定此原点”先新建身份，再重新读取绑定预览，绝不把旧活动身份当作新角色覆盖。另有明确更新当前身份的操作，编辑此身份会影响所有使用它的卡。原点原文与会话进度保留。

人物基点加当前角色卡、自由点子两路先向所配AI生成完整草稿，用户核对后另存原点，再明确绑定。模型原答与编辑草稿可保留和导出；真实AI结果仍需审阅。

“使用并绑定”默认保存本聊天锁定及当前角色卡连接，群聊只连该群；全局默认需要单独勾选。原生persona目录是活动名称/设定/头像/注入的唯一真源，原点引用固定版本，会话账本负责当局进度。切换同世界原点身份同时更新当局人物关联；不改历史署名、不清空进度。跨世界身份要求先适配。

设置、聊天和档案写入分阶段核对；部分失败保留恢复标记，“继续核对绑定”可恢复，生成前拦截未完成切换。原点写回失败可在管理页“继续核对原点绑定”恢复。来源被删或版本不符会停止引用，不自动换人。原生完整控件保留头像裁切、复制删除、称号、注入位置、世界书、备份恢复和历史署名操作。

创建使用 TT 2.4 的真实 `/api/avatars/upload`、导出 `initPersona` 和确认保存回读。独立 UUID 文件名上传前查重，采用真实响应路径，初始化前再检查未被其他资料占用。接口未连接时创建按钮明确不可用，已有身份选择仍可使用。保存失败可继续核对同一实体，不重复上传。上传结算不明、响应路径错误或在上传中切卡时停止后续操作；晚到回执只留在内存直至原作用域确认保存，不能声称重启仍可恢复。未知上传禁止自动重传或改用活动身份。

首次引导由 `identity-onboarding.js` 提供只读判定及单层页面。新卡没有关联时提示创建/选择，真实新聊天提示沿用/更换；确认才写绑定。旧聊天有有效锁时直接恢复，失效锁显示修复。原生全局 auto-lock 不等于用户已给新卡选择身份。

TT 2.4 源码 `getChatResult` 在 `await CHAT_CHANGED` 完成后发 `CHAT_CREATED`；群聊为 `GROUP_CHAT_CREATED`，原生 persona 选择在 CHAT_CHANGED listener 中完成。原生空开场不会置 freshChat，因此不发 CHAT_CREATED；此边界不能仅凭无 metadata 自动判新聊天。`default_user_avatar` 从 `/script.js` 导出，`initPersona/getUserAvatars` 从 `/scripts/personas.js` 导出。创建 gateway 不自行静态导入宿主模块，入口须显式连接。

开发接口：`createNativePersonaGateway({getContext,getAvatar,defaultAvatar,initPersona,persistSettings,readAvatarIds})` 注入 `createIdentityService({nativePersona,...})`；服务新增 `create({name,description,revision})`、`resumeCreation({revision})`，返回完整当前绑定状态。gateway 只创建，不切换身份；service 才提交当前卡/聊天绑定。`mountIdentityOnboarding(container,{service,newChat,onDone,onManage,onClose})` 的 onDone 在保存完成且允许离页后调用；卸载后的迟到结果不刷新替代页面。

`index.js` 已连接上述真实宿主接口。所有玩家入口仍进入同一个用户身份页面：未绑定先显示引导，完整管理为内部跳转。已知新聊天事件自动打开沿用/切换提示；已有未保存编辑时保留当前页面并显示同一入口通知。无卡关联时聊天底部显示创建/选择提醒，展示不写任何绑定。引导草稿返回设置后按卡与聊天保留，重新打开恢复；重复新聊天事件不会重复打开。空开场缺少宿主事件的边界仍保留。
