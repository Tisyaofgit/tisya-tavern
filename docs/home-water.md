## 数据与生命周期

身份用角色索引 + avatar，读取前后和切换前分别核对；同名角色不会合并。聊天按宿主 timestampToMoment 解析 last_mes 并倒序排列；无有效时间的条目保留相对顺序且不编造日期。选择使用对应原 file_name，等待宿主选择完成并核回当前角色和 chatId。旧选择完成后不会关闭已切换的新页面。

四路元数据请求，各十五秒；失败在该角色内可见，不当空会话成功。退出、刷新、切页面与卸载取消在途读取，忽略迟到结果。首屏最多 24 位角色，前两位展开，每位六条；再展开以及搜索都访问完整已读元数据。搜索不读全部聊天正文；未读部分明确显示进度。其它角色返回时不重建已经显示的聊天按钮。

USER 性别只识别当前 persona_description 中单独的明确字段，不推断姓名、头像或其他角色。缺失/冲突暂沿女相，不显示说明；第三相待审图；不改用户资料。男女素材分别加载，脸颈区域保持几何稳定。Canvas 跟随 requestAnimationFrame，绘制上限约24次/秒；暂停、系统减少动态、文档隐藏和销毁均停止调度；可见WebView的短暂失焦不停止，销毁后不能复活。静态深水底由 CSS 承载。资源尺寸/加载失败明确说明，导航不依赖素材加载完成。

## 验证边界

Node 完整构建与回归；Happy DOM 使用生产初始化器和 home 模块，画布在该层用桩；Chromium 153 使用生产 home、CSS、字体和全部素材，数据与宿主边界为隔离夹具。检查 320×700、430×932 男女、768×1024，无横溢出、页脚不压会话框，选择/搜索/销毁与动态暂停/恢复/减少动态通过。示例图中的角色及聊天是排版夹具，不是读取用户数据所得。
