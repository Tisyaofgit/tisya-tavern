缇斯亚虚拟手机 · 统一表单与下一轮联合收发

本说明按现行统一表单代码整理。生活应用和原17类网络页面共用当前聊天的手机服务与 Matrix 表单数据库；本文中的联合收发协议继续适用。安装版本以 manifest.json 及同次交付的固定提交、构建与恢复记录为准，历史快照不代表当前安装包。

世界、人物和手机配置的现行填写规则见 templates/README.md 与 templates/form-authoring.md。内置模板书是 templates/tisya-template-book.json；world-form.json、character-form.json 是填写计划，不是另一份运行状态。旧 phone-world.json、phone-character.json 及旧初始化块只保留作迁移来源。

一、这次确定的运行方式
手机中的发送、回复、搜索请求和赞踩首先记录为稳定ID的操作；下一轮主剧情API获得附加提示块，与正文在同一次请求中生成。正文仍按原协议组织，网络增量写入现有唯一extra容器中的phone子块。没有新增独立模型调用，也不借用或清空宿主输入框。

正文中的[[手机:m1]]只显示当时已接纳的数据。页面下方的手机扩展与输入区手机入口打开当前完整状态。原始消息、主剧情正文、其它扩展块保留。标记不是“再让模型写一份小卡片”：模型只给引用，代码从同一个事件日志重建定格页面。

二、安装、宿主入口与独立预览
1. 完整扩展：按本次交付所指定的候选提交或完整安装包更新匹配版本的 TauriTavern。manifest.json 加载 runtime.js 与 shell.css；保留同一版本的源码、构建产物、phone.html、配置与资源目录，更新后完整退出并重开宿主。现行入口使用 TauriTavern 的原生接口；仅有相同扩展目录结构，不能推定任意 SillyTavern 版本都兼容。此扩展不是 Tavo 的 TPG，单独打开 phone.html 或修改文件后缀不能完成扩展安装。
2. 正式聊天入口：先打开所属聊天。输入区上方快捷栏的“手机”进入网络与消息；桌宠手机第二页按所选世界开放生活应用。生活手机设置中的“打开网络与消息”回到同一服务的网络页。生活应用需要在现行用户身份／表单流程中选择当前世界和人物；缺少设置时通过“核对身份与世界”处理，已有进度不会因重开页面而套用默认初态。
3. 独立 HTML 预览：phone.html 顶层单独打开时使用演示资料及独立预览存档，设置里的“待发送内容／接收本轮内容”可手动核验联合收发。它没有当前主聊天 API，也不能独立初始化依赖宿主世界与人物配置的生活手机。嵌入聊天的页面通过 window.Tisya.phone 取得服务，并核对打开时的聊天归属；接口缺失或归属变化会报错，不改用预览档顶替。

正式聊天的网络页初始配置只建立本人账号和通知箱；生活应用从所选世界和人物的现行表单读取。独立预览的 Glanz 新闻、票价、私信与舞台数据不会自动写入用户世界。下一轮根据已有剧情、已知账号与真实故事时间生成需要的页面，没有依据的内容保持空白。网络应用目录保留17类入口，生活桌面的应用则由所选世界配置决定。

旧安装 ZIP 与 PHONE-RESTORE.json：仓库保留的 PHONE-RESTORE.json 是2026-11-09冻结的旧手机候选快照，记录1193个文件，基线为72522564bfe75a80298396d4636c48c6f34f7d57。其 head_commit 明确只是发布前观察到的 HEAD，最终候选身份须由那次 Git 发布回执绑定。该文件及旧 ZIP 只用于恢复对应历史版本；本说明不把它们当作现行候选的安装清单、构建哈希或新包交付证明。

三、17类应用
forum小组；weibo微博；artist艺人主页；notice公司公告；news新闻；trends热搜与站内搜索；fanclub粉丝社区；live直播回放；video视频／短视频；music音乐与榜单；schedule公开日程；ticket票务；group群聊；bubble订阅消息；dm私信；inbox通知；timeline事件时间线。

当前直接发送与评论：forum/group/bubble/dm/weibo/video。公告、新闻、作品等为阅读页面，可由下一轮增量更新。粉丝投票、关注、收藏、票档意向、已读等沿对应页面按钮处理。票档意向不产生现实订单。网络页保留分镜与时间轴呈现；生活相册、音乐及正文媒体引用可读取已登记且有权访问的原件，没有实际原件或播放权限时不伪造真实音视频。

四、用户操作到模型的链路
发送时正文立即写进所属消息流，动作记录只引用楼层或条目ID。相同名称的账号不会合并。操作状态：queued待发；sent已附加本轮请求；received已确认处理；failed接收失败、原内容保留；cancelled已撤回未发动作；detached属于已离开的剧情分支。

高楼提示词默认取最近40条，补齐本轮操作所指原文和必要引用链；完整历史不删除。目录提供下一楼编号和稳定账号，旧回合重放使用原捕获边界。若必要引用闭包超过160条，明确报出上下文过长，待发内容与原楼层保持原样，不断开引用冒充完整。

请求准备时捕获requestId、原生用户消息锚点、操作ID、所属分支与事件边界。正文工具轮或重复组装取同一份捕获值，不重排事件。已准备请求期间允许阅读、搜索已有内容和编辑草稿，暂不改变楼层或赞踩；正文结束／明确失败后恢复。这样模型拿到的下一楼编号不会被中途操作挤掉。

停止、无phone块、错误JSON、错误ack、引用不存在或保存失败，均不确认消费待发动作。正文仍保留。若重开或切聊天后无法确认旧请求是否结束，会保留待回状态；只有用户确认原生生成已结束，点击“上轮已结束，恢复待发”，才恢复未处理操作。该按钮不调用模型，不删除主聊天消息，不复制已发消息。

五、模型输出
既有正文结束后，在原有extra里加入唯一phone子块。以下表示结构，requestId与ack需使用本轮注入的真实值，不照抄示例编号：

<extra>
  <phone>{"requestId":"本轮真实请求ID","acks":["已处理的动作ID"],"blocks":[{"type":"forum","thread":"forum-encore","items":[{"by":"forum_night","text":"新回复正文","quote":9}]}],"markers":[{"id":"m1","thread":"forum-encore","floor":10}]}</phone>
</extra>

在正文适当位置写：[[手机:m1]]。
上例仅适用于已有1～9楼、本轮新增回复落10楼的情形。标记引用始终按实际本轮结果。复读、显式楼号、删除墓碑、计数set/add等沿网络区块原协议；未知数量不能补0。引用楼层只写quote整数，复读用repeat的sourceFloor或text、ids与n。

phone顶层字段：
requestId：必填，必须匹配当前请求。
acks：已处理操作ID数组，必须属于本request且不可重复；遗漏的操作保留待发。
blocks：只写新增或变化的区块，不重发整套历史。
accounts：新账号映射，可省略；已有同名不同ID仍独立。
documents：新页面列表，可省略。
markers：定格标记，结构为{id,thread,floor?}或{id,thread,itemId?}；整页标记可省略楼层／条目。floor与itemId不能同时出现。

新账号例：{"actor-chat":{"name":"角色昵称","platform":"wechat","personId":"稳定人物ID"}}。
新群聊例：{"id":"group-new","kind":"group","title":"群名","visibility":"private","audience":["me"],"author":"actor-chat","at":"2026-11-09T20:00:00+08:00","meta":{"coreThread":{"platform":"wechat","baseTime":"2026-11-09T20:00:00+08:00","stepSeconds":30}},"items":[{"by":"actor-chat","text":"首条消息"}]}。
新流从1楼开始。forum/group/bubble/dm的默认平台依次为douban/wechat/bubble/dm，账号platform需相符；本人me跨平台使用。非流评论使用稳定itemId，视频author与by按只读投影兼容。

JSON只当数据解析，不执行脚本。代码围栏中的协议示例不接纳；重复phone、歧义extra、危险对象键、坏引用整批拒绝。JSON字符串里的关闭标签不会提前终止读取。模型不能冒充me发帖、删除me的消息、改现有页面visibility/audience/author，也不能写readerState或重置coreThread。

六、搜索、赞踩与权限
“公开内容”搜索只查当前公开记录的标题与可见正文；“我的手机”可查本人可见私聊与订阅消息。阅读选择、后台meta不进搜索全文。已有结果立即返回；“随下轮继续查”才加入请求。新的搜索结果属于虚构世界资料，应给来源页面；它不是现实互联网搜索。

赞与踩互斥，再点当前选项可撤销；已知计数按本地选择变化，未知总数只显示已选择，不造总数。非流评论保留来源计数，由阅读投影加本人变化，避免原条目同时出现两个可编辑版本。模型收到的是用户已经做过的动作，不应重复加同一个赞。

角色知情与读者可见分开：当前待回复私聊正文只进入对应相关上下文，公开引用只带公开来源；私人会话目录仅帮助定位，不让其他角色自动知道私聊内容。程序能约束数据范围、身份和引用；具体文本是否合乎角色知情仍需真实模型联调验证。

七、定格与当前手机
接受的模型增量保存为事件；定格记录只保存来源消息UID、原始候选SHA、分支、事件边界与标记引用。旧正文重建的是这个边界上的数据，即使后来新增楼层或赞踩也不变。

原生重骰、删除、切换候选时按当前选中的稳定来源顺序重建当前手机；退出的通知不再进入当前通知列表，旧快照保留。后续分支上的用户动作若已没有当前来源，标为detached，不悄悄搬到新分支。

冻结iframe仅可读所属聊天和指定来源。初次正文先渲染、增量后保存时，显示正在接收并监听同一来源就绪；不会用当前值填空。下面的完整手机可操作最新状态。跨聊天、跨源或迟到请求拒绝写入新会话。

八、数据真源、绑定、媒体与恢复
正式手机的当前状态由 Matrix 统一表单数据库保存。index.js 通过 engine/host.mjs 的 createPhoneDatabaseBridge，交给 engine/phone-database.mjs 的 createPhoneDatabaseStorage 读取与提交；phone-app.mjs 的 bootPhone 复用这个宿主服务。默认持久存储为同源 IndexedDB 的 tisya-engine-v1／chats，会话由 chat_uid 定位。chatMetadata 中的 tisya_engine 保存会话身份、归属等元数据；旧“缇斯亚虚拟手机”槽不是现行手机的第二份真源，也不再与表单双写。

世界、人物、规范余额、当前世界时钟、网络内容与手机历史共用同一数据库。X_PHONE_BINDINGS 记录手机视图绑定；当前时间来自 X_WORLD_CLOCKS，余额与业务明细写各自规范表。发送正文在 suite 事件中保存，待发动作引用它；界面、搜索、通知和定格从已保存数据派生。表单提交核对稳定操作ID、聊天归属与修订号，同一ID不能换内容，旧修订不能覆盖新数据。这个提交边界不涵盖媒体库、聊天元数据和宿主磁盘之间的所有步骤，不宣称跨库原子事务。

生活手机绑定所选世界、人物、聊天载体及原生用户身份。打开前后都会复核选择；已有手机只读取对应实例，重开页面、重选模板和更新内置书不重复初始化。当前选择与既有进度不符时，先回到原聊天或核对身份与世界；不会自动改归属、清空进度或搬到另一人物。旧 <手机世界>／<手机初态> 与旧模板必须作为只读来源核对迁移差异，不能直接创建一份独立手机运行态。

媒体资料和文件原件分开保存。表单保存相片、歌曲、可见范围及稳定资产引用；生活手机导入的图片、视频、音频原件保存在 tisya-phone-host-media／assets，按媒体来源聊天、世界／人物绑定和资产ID隔离。同一资产ID已有不同字节时拒绝覆盖。图片编辑生成关联原图的副本；整理当前相册不改写已分享内容或历史。合法原生分支可沿已验证来源引用原件，普通导入不能借另一聊天的缓存。旧正文只读取该冻结来源已登记的媒体，不因打开阅读页新建媒体或扩大授权。

生活手机设置里的“导出手机存档”导出 tisya-phone-host-backup 格式，包含手机归档，以及当前状态、保留事件、请求快照和旧正文帧所引用的媒体原件。缺少任一必需原件、归属不符或导出期间修订改变时中止，不把残缺结果称为完整备份。导入先核对聊天、绑定、媒体来源与修订，再由用户确认替换；主请求在途时仍受手机导入限制。媒体写入与表单提交不是一个跨库事务，失败须根据实际错误核对原件和状态，不静默清空后重建。

网络页的手机 JSON 导出与独立 HTML 预览存档不包含另一媒体库的文件原件，也不能代替整个统一表单数据库的备份。恢复正式运行环境，应同时核对所属聊天的统一表单状态、手机归档和所需媒体；仅有 chatMetadata、源码 ZIP 或 PHONE-RESTORE.json 不足以恢复用户运行数据。独立 HTML 使用单独的本地预览键；损坏、配额失败或并发冲突会明确报错，不自动切换到另一份存储。

十、开发和核验入口
完整交付应包含相互对应的实际源码、runtime.js 与单文件 phone.html。现行接线可从 index.js 的 getPhoneService／openVirtualPhone／window.Tisya.phone，依次核对 engine/host.mjs、engine/phone-database.mjs 与 phone-app.mjs 的 bootPhone；生活媒体与完整备份见 phone-life/host-app.mjs、phone-life/media-archive.mjs，冻结媒体读取见 phone-life/presentation-media.mjs。

开发环境按 package-lock.json 安装依赖。修改手机模块后先运行 python3 tools/build-phone.py，再运行 npm run build:extension；python3 tools/build-phone.py --check 核验单文件手机与源模块一致。npm test 运行 package.json 明列的生成检查与 tests/*.test.js；tests/phone-bundle-dom.mjs 不由该通配符覆盖，需用 node --experimental-vm-modules --test tests/phone-bundle-dom.mjs 单独运行。后者使用 Node ESM VM 与 Happy DOM，仍属于模拟，不提供真实浏览器布局结论。

PHONE-RESTORE.json 与 docs/validation/phone-20261109/verify_phone_snapshot.py 保留旧快照契约：只按该清单对应的固定源、字节与最终 Git 发布回执恢复历史版本；清单自排除及 head_commit_semantics 规则保持原义。新交付需使用同次冻结的源码清单、验证结果、恢复映射与保存回执，不能重用旧日期清单冒充当前校验。

PHONE-PROMPT.txt从实际prepareTurn导出固定附加提示词，便于审阅；动态动作、当前请求ID与相关上下文必须由核心实时附加，不能拿静态提示词代替完整收发链。具体环境中的HTML预览如果限制脚本或浏览器存储，请下载后在独立浏览器标签打开。
