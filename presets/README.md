# 缇斯亚完整预设与任务协议

当前试用主预设：`Tisya.json`，酒馆内名称 **Tisya**。随 `trial/reply6` 分支内置，启动时通过原生接口按修订同名更新。首次改用它时选择一次即可，以后无需手动导入。同一修订重启不回写手改内容；新修订更新同名提示条目。其他名字的预设和聊天数据保持原样。

`Tisya-One-Pass-1.json`、`Tisya-Six-Blocks-1.json` 与 `Tisya-TauriTavern-0.2.0-alpha.13.json` 保留为历史兼容或手动导入入口，不是当前自动同步主预设。

使用快捷菜单第一项“配置”：本模式／主题／世界／预设与 API／上下文与数据。主文风在世界页输入、检索、保存、再选择；未选择时不附加默认文风。模式扩展、标记和工作流增强同样先保存再选用。预设本身只保留固定身份与协议及动态装配入口，不含资源目录。

本模式页保存后，以其心声方向配置为准；尚未保存方向覆盖时沿用当前原生预设开关。结构化输出的总开关仍是原生“输出 · 十块结构”。关闭可选内容不改变原协议的合法空容器。

通用、模式和任务的 API／预设分别继承。初次可都留空，继续使用原生当前连接与本预设。生成后通过“上下文一览”核对实际装配消息。配套叙事目前使用普通生成，Agent 适配接口预留。

原生角色卡正则可覆盖普通开场白及已解析的结构化正文。主题页默认允许该兼容路径，实际脚本启用和授权仍由宿主管理。扩展更新不会覆盖已导入的预设，仅更换 JSON 版本时需要手动导入并选用。

此预设依赖扩展的 `tisya_live_*`、`tisya_config_selected` 及原输出宏。没有对应扩展时不可作为独立预设使用。旧 alpha.10／alpha.12 文件保留供回溯。

alpha.14 在本模式页新增「思维链详细程度」三档：完整、精简、仅格式与配置。默认精简，保存后下一请求生效，配置随世界／聊天隔离。

alpha.15 将记录校验与公开面板读取分开。alpha.16 接入 A–E／a–e 和权限栏公开标记 ~，撤销强制四格提示；已有精细权限继续有效。无对应目标的权限行单独提示，不再阻塞独立有效的记录。关闭 MVU 时同步移除相反的操作模板。

alpha.18 修正心声指令：选 N 个方向，开篇与收篇各 N 条，分别评任务／开局与正文实际进展；不再按方向拆分上下位置。配置页已同步说明。精简档复用一份授权／视角要求，辅助字段只写必要结论。动态宏入口未变，更新扩展后下一次生成生效，无须重导本文件。解析器和气泡修复对已有消息的读取生效。

原卡正则的世界扩展改为无月潮外框的直接布局，保留原卡自身的小球／折叠；静止模式的入场动画直接显示完成状态。该显示变更不改变预设字段或卡片源文件。

## alpha.31.31：全部已接入文本任务

11种专用表单任务、8种通用文本任务和场外交流默认各选专用完整预设：会话前缀、三段身份、模式授权、预处理、完整材料、登记规范、内部工作流、assistant就绪、system警告及唯一执行尾部。人物提炼导出同样附完整协议和本次全部字段定义。任务保持各自JSON、分组表或文本输出，不强制故事十块格式，不要求输出隐藏推理。

在“模型与预设 → 任务连接分配”可指定对应的自定义任务预设。完整任务预设可编辑条目，保留 task 标识及必需入口/材料槽；缺失、重复、错任务或混用故事预设会拒发，并提示改选配套预设。不会覆盖、自动迁移或修剪用户原稿。选择“不使用附加预设”也不能绕过缇斯亚任务的基本协议。

“数据与诊断 → 请求检查”展示实际完整有序消息，包含所有前后缀和材料；尚未调用的任务没有实际请求快照。Agent、嵌入、重排、绘图和语音仍为独立能力/预留执行器，不冒充已验证的文本任务。正式模型行为与Android需分别实测。
