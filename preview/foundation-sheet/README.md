# 基础表单与动态提炼 · FT07 / R5

可直接打开 dist/foundation-sheet.html。所有资源内嵌；草稿只在页面内，保存草稿后可导入继续。无模型连接、网络、正式存档写入或自动后台保存。

## 使用

1. 选择表单或建立人物，手工输入已有值；AI只取得空白格。
2. 在“人物子表”反复添加前史、关系、隐情，分别编辑；勾选本次交给外部模型填写的子表。未勾选不纳入整份任务，隐情默认不勾选。填写依据是用户主动粘贴的原文，不随子表勾选自动删改，请核对资料范围。
3. 打开“AI填表”，粘贴资料，选择当前组或整份人物，导出TXT交给外部模型。
4. 将完整结果粘回“检查并回填”。所有选中记录一起校验，一项失败则整个批次不写；错误保留原稿，修好可重试。成功只表示结构有效，语义仍须核对。
5. 保存草稿。手机浏览器下载/导入和视觉布局待Android实测。

## 极简文本

分组标题＋稳定行号＋字段名＋值；字段名后的冒号可有可无。单表可省分组；跨子表保留分组。允许纯文本代码块；未知值留空但保留行。新任务不要求Markdown竖线、分隔行或HTML转义；旧单表Markdown继续兼容。

仅texts/refs字段按分号拆多项，普通文字标点原样保留。列表“无”或[]表示明确空列表；空格/顿号不猜分项，避免拆坏人名。需要字面分号的单项可手动在表格编辑；模型填写的任意嵌套 array/map/object/json 格改为共享简表：保留字段行，后续完整简表各行缩进两个空格；内部子表也一起缩进。程序解码后仍按原类型与引用授权校验。手动本地单格编辑器与草稿导出继续保存结构数据，不属于模型输出协议。

名字只在当前获准对象集合内解析成内部稳定ID；同名用所列区分名称，无法确定则拒绝。可使用本批次新增名称引用该已授权对象，不创建隐含新对象。当前预览可选引用只列对象表，事实/隐情标题不会混进默认名单。

## 关联归集

人物子表保存独立记录与父人物绑定，绑定不表示知情授权。前史/关系主体由父绑定填入。对象字段从本表ref/refs字段及父人物汇总、去重，不扫描正文、不推出知情或传递关系。人工对象值不覆盖；自动值在关联格更新时重算，导出恢复保留自动标记。秘密的关联对象仍需填写者判断，程序不纠正语义。

R5在前史末尾追加第12行“涉及对象”，用于明确涉及的物品等，不改变旧行号；进入对象汇总，不进入参与者或知情者。旧草稿恢复后该字段仍未知。以39字段＋2前史＋2关系＋1隐情作示例，新空白任务为81格；原79/88格任务按冻结R4字段目录回放，不伪装成新任务通过。此数量仅为示例，不规定实际子表数量。

## 动态叙事提炼与接口请求

`node tools/foundation-narrative-roundtrip.mjs prepare NEW_OUT [MODEL]` 生成真正的Chat Completions请求JSON及冻结上下文；只输出各类子表的一份定义，模型自己提炼条目数量。测试资料仍用完整R4叙事，便于对照字段说明修订的效果。预览UI仍是手选子表，动态适配器尚未接入该UI。

`node tools/foundation-narrative-roundtrip.mjs replay CONTEXT RAW_RESPONSE NEW_OUT` 原样保留响应，验证版本、完整性、字段、引用与前史摘句。失败无正式写入，也不修改原上下文。旧R4请求须使用其冻结代码，不绕过版本散列检查。解析通过不代表语义通过。

R5澄清性情与能力、仪态与节奏、改变条件与他人期待、稳定边界与单次决定；不得由句子顺序补时间顺序，也不得倒推因果或选择。关系可指人物、组织、地点、物品等有依据的持续联系，责任不等于私交。规则位于字段定义与适配器，不把本题答案嵌入提示词。
