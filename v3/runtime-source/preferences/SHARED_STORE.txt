Production preference storage: P is the only confirmed bank

The existing pure functions remain the validators and state transitions.
Production assembly uses shared-store.mjs, with two distinct durable owners:
  B: current {chatId,branchId}; story journal, pending drafts, acknowledgement receipts.
  P: fixed {chatId:'tisya-preferences',branchId:'global'}; confirmed contributions,
     source history, activation and confirmation receipts across sessions.
P uses the real 2.4 worldbook storage transport and one disabled entry. It is never
automatically activated as a worldbook. P's bookId must remain stable across chats.

Assembly
  const sessionStorage = createWorldbookTableStorage({transport,bookId:sessionBook,
    owner:{chatId,branchId},initialState:initialRunnerState});
  const preferenceStorage = createWorldbookPreferenceStorage({transport,
    bookId:sharedPreferenceBook,registry});
  const storage = createPreferenceOverlayStorage({sessionStorage,preferenceStorage});
  const runner = createPreflightRunner({storage,...runnerDependencies});
  const preferences = createSharedPreferenceService({sessionStorage,preferenceStorage,
    getSessionOwner:()=>({chatId:actualChatId,branchId:actualBranchId}),
    isEnabled:()=>actualPreferenceSwitch,
    getProjectionOptions:()=>({context:actualContext,world:actualWorld,
      persona:actualPersona,binding:actualBinding,activeSourceKeys:retainedSources})});

Runner calls keep their existing signatures. read() overlays P's rows/history and
revision fingerprint temporarily; compareAndWrite() strips that projection before
writing B. A stale or altered P projection is rejected. Existing confirmed banks in
B are rejected for explicit migration, instead of silently creating two authorities.

Confirmation is recoverable, not cross-store atomic:
  1. Validate B's pending draft against the actual P contribution versions.
  2. Persist P contributions/history plus a fingerprinted receipt bound to B owner
     and draft ID; verify direct readback.
  3. Mark B's draft accepted and store the P receipt reference; verify readback.
If step 3 fails, retry confirm(id) in the same session/branch. The P receipt completes
only B's acknowledgement; it never adds the score or reapplies a mutation again.
An interrupted P write is likewise resolved by reading its persisted receipt.
The facade reports persistence errors rather than claiming both writes succeeded.

Global contributions remain available from a new, empty B. Explicit scope IDs still
filter them. Non-global contributions without an explicit session scope receive the
actual chat owner, preventing a reused source ID or independent feedback from leaking
into another chat. Ordinary feedback also follows retained source keys; independently
confirmed feedback:<id> survives candidate rerolls within its confirmed scope.

Every shared contribution retains preferenceOrigin:{chatId}. Ordinary source identity
is (stable chat ID, original source key, preference group): two chats may both supply
user:1 without colliding; another branch of the same chat cannot count it again.
feedback:<UUID> retains its independent UUID identity across branches. Mutation history
likewise retains feedbackOrigin for ordinary feedback keys. Original source strings,
signed scores and excerpts stay intact. projectPreferences accepts a top-level stable
chatId, distinct from a display name or host chat filename.

Methods
  confirm(id,{expectedRevision?,now?})
    expectedRevision refers to B. Result includes preferenceRevision and recovered.
  reject(id,{reason,expectedRevision?,now?})
    rejects only a pending, uncommitted B draft; review history stays in B.
  setEnabled(rowId,boolean,{reason,expectedRowRevision?,expectedPreferenceRevision?})
    updates only P, retaining the source score and before/after history.
  project(options), list()
    read the single P authority; a disabled switch returns empty lists.

No cross-window CAS or cross-store atomicity is claimed. These adapters retain the
host's managed single-controller serialization, version guards and direct readback.

Verification
  node --experimental-vm-modules --test \
    w24/implementation/preferences/preferences.test.mjs \
    w24/implementation/preferences/shared-store.test.mjs

The added tests cover another branch/new chat, private scope isolation, P success
followed by B failure and recovery, P changes blocking stale writer persistence,
duplicate-authority rejection, disabled operation, and actual 2.4 transport reload.

W25 explicit manual revision API:
  revise(rowId,completeValues,{reason,expectedRowRevision,operationId,expectedPreferenceRevision?})
  Revises the same confirmed contribution in P, keeps source/origin/access and row ID, increments row revision once, records full before/after history. Score/scope/evidence edits are user-confirmed only; automatic feedback mutation remains activation-only. Historical source-group identities are reserved against reimporting the same feedback after manual regrouping.
  setEnabled also accepts operationId; stable manual operation receipts recover write-success/acknowledgement-loss without applying the edit again.
